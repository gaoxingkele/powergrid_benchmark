# Applied Sciences 双稿与闽投六稿的流程蒸馏

## 2026-08-13 补充：超时进程树隔离

P6 暴露了一类传输层失效：直接的 Codex 进程已经超时，但 runner 与 Node
子进程仍可能持有隔离 worktree 的句柄。Harness 0.2.3 因此让每个新的真实
传输调用进入独立进程组/会话；超时时仅终止该次调用创建的受控进程树，确认
回收后返回 124。框架不会自动终止既有孤儿进程。恢复仍须保留日志和 WIP
patch、确认目录解锁，并从干净基线重试同一个已批准目标。

本记录把 MA-SQLGrid、C²GES 和闽投六篇的实际修改经验转化为可执行的论文
Harness 规则。它记录的是质量控制边界，不是录用保证，也不替代作者对投稿内容、
作者身份、基金、数据权利和最终提交的确认。

## 1. 为什么 Applied Sciences 两篇需要叙事重构

两篇稿件的共同问题不是缺少文件或测试，而是主文把复现与审计材料放在研究故事
之前。MA-SQLGrid 的科学主线应是五角色生成—验证—裁决流程及历史候选池中
`80/180 -> 100/180 -> 101/180` 的观察；C²GES 的主线应是结构感知的来源链接
抽取、与基线的等句数比较，以及路径删除项未改善 ROUGE-L 的组件诊断。版本史、
哈希、事故目录和完整测试矩阵仍有价值，但主要属于补充材料。

由此形成四条通用规则：

1. Results 按研究问题和证据强度排序，不按项目执行时间排序。
2. 负结果在摘要、结果、讨论和结论中保持同一方向与限定。
3. 标题中的每个强词必须在方法中操作化，并有直接实验支撑。
4. 可审计、可复现和可追踪是可信度属性，不能替代性能、语义正确性或人工效用证据。

## 2. 闽投六篇暴露出的共性问题

- P1：原始 DAY_AHEAD 表没有 issue timestamp 和数据 vintage，24 h 任务只能解释为
  retrospective delivery-row lag；新实验还显示 Persistence 在主要 cap 条件下仍有优势。
- P2：所谓 curvature 实际是温度/距离缩放；24 h 点预测不能自动写成完整 day-ahead
  trajectory；精确层级的一致性边界必须单独说明。
- P3/P4：共享候选生成器、场景和 AC 映射资产，必须对称披露；代理目标、标准
  hypervolume 与 AC 诊断是不同证据层。
- P5/P6：事件计数或运行级日志不等于可审计的完整决策轨迹，更不等于人工解释质量；
  preference/local-search 贡献需要匹配预算和机制对照。

共同的修复顺序是：先冻结标题—任务—贡献合同，再补方法—代码映射，之后才运行
可识别实验；结果方向确定后重写叙事，最后做独立评审、最终完整性和人工投稿门。

## 3. 2026-08-13 实际运行产生的新规则

### 3.1 独立复跑不能只比较一个总哈希

P1 `p1_s3_fair_v1` 的独立复跑中，510 条记录的所有科学字段一致，四张聚合/统计表
逐字节相同，但每行 `runtime_s` 不同，导致原始 CSV 总哈希不同。正确报告方式是分别
核对脚本、配置、输入、科学字段、派生表和环境/计时字段，不能把“科学结果复现”
夸张成“全部字节相同”。

### 3.2 稀疏工作树必须区分读依赖与写权限

共享 Mintou evidence 树是六篇回归测试的只读输入。若把它加入 `allowed_write_paths`，
会错误扩大脏基线与合并范围。Harness 0.2.2 新增 `read_only_paths`：共享树可进入
sparse checkout，但不进入允许写入范围。

### 3.3 超时不是论文失败，也不是可接受候选

P2/P3/P4/P6 的宽阶段在固定 1800 s 窗口内未完成。恢复协议为：

1. 保留原 worktree 和日志；
2. 导出二进制 WIP patch 并记录 SHA-256；
3. 明确标记该 patch 不是候选或科学证据；
4. 修复基础设施后从干净基线重跑同一已批准目标；
5. 若科学目标本身要拆分或改变，则创建新计划并重新人工批准。

Harness 0.2.2 支持 `PAPER_HARNESS_CODEX_TIMEOUT`，但延长时间不能替代阶段范围预检、
心跳或检查点；这些仍是后续改进项。

### 3.4 接受操作必须串行

六篇位于同一个 Git 仓库。并行 `accept` 会竞争同一个主分支，可能产生伪冲突。
当前运行采用串行人工验收；框架后续应增加仓库级 merge lock，并在锁外继续允许
相互独立的执行阶段并行。

## 4. 六阶段标准模板

1. Claim contract：标题、任务、贡献、主估计量、负结果、共享资产与人工阻断项。
2. Method contract：公式—代码—配置—数据处理—随机性—预算的逐项映射。
3. Identifiable experiments：匹配预算控制、独立运行命名空间、分析单位和停止规则。
4. Results narrative：只从已接受结果重建表图和全文叙事，不按“好看”筛结果。
5. Scientific closure：逻辑、方法统计、理论创新三维独立评审与修改闭环。
6. Human submission gate：作者、单位、通信邮箱、CRediT、基金、APC、许可和最终提交。

前五阶段可以自动辅助但必须逐阶段验收；第六阶段不能由 Harness 推断或代替作者。

## 5. 投稿质量的终止条件

“一次投稿就中”无法保证。可执行的终止条件是：没有未解释的标题—证据错配；没有
伪造或无法追溯的数字；主要比较的预算与数据可见性清楚；负结果不漂移；共享资产
披露完整；当前 PDF 与图表/参考文献/声明动态一致；所有无法由本地证据确认的事项
保持为人工 blocker。达到这些条件后，稿件可以进入作者最终核读与投稿，而不是被
描述为保证录用。
