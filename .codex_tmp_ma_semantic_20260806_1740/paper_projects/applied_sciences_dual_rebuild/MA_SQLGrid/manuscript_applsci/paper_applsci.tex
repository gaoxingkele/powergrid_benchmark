\abstract{Power-grid text-to-SQL requires read-only execution and intended results. We evaluate \masql{} with two frozen, GridDB-tailored prompt factors: a context package and a structural/SQL-operation hint. Qwen2.5-Coder-7B Q4\_K\_M and Granite-3.3-8B Q4\_K\_M were evaluated in a paired 2-by-2 design over 180 questions (1440 predictions). After Holm adjustment, no factorial execution effect or cross-backbone modifier met the declared evidence rule; projected-column adherence increased under the hint. In a frozen 700-call component study, presented value evidence improved Qwen execution by 0.1059 (95\% composition-sensitivity interval [0.0282, 0.2013], adjusted $p=0.0310$) but not Granite execution; deterministic selection did not meet its declared rule. We then re-executed every archived prediction on 15 deterministic semantic stress states and three insertion-order diagnostics. Two separately executed, prediction-blinded automated protocol screens retained all 114 order-sensitive questions, leaving 66 for an automated endpoint. The 15-state logical-AND execution-agreement rates ranged from 0.6212 to 0.8182; none of nine effects survived Holm correction. This was not qualified human semantic review. GridDB is a synthetic, development-visible 8-table/98-row database; no multi-run replication or external accuracy is claimed. The evidence supports a bounded case study, not a universal prompt recipe.}

\section{Introduction}
Power-grid engineers routinely work with relational records describing equipment, inspections, maintenance orders, defects, and operating conditions. Direct SQL access is precise, but it assumes that a user knows the database schema, joins, identifiers, and aggregation conventions. Text-to-SQL systems promise a more accessible interface: a user asks a question in ordinary language, and a model produces a query whose execution returns the requested records. In an engineering setting, however, plausible-looking SQL is not sufficient. A query may execute against the wrong table, omit a required aggregation, return an unintended projection, or silently use an identifier that exists but has a different domain meaning.

Modern language models can translate questions into SQL when supplied with schema context, demonstrations, or constrained decoding. Established benchmarks such as Spider emphasize generalization across databases, while constrained decoders such as PICARD show the value of preventing invalid token sequences \cite{yu2018spider,scholak2021picard}. Subsequent work has explored schema linking, execution-guided selection, prompt design, and large-language-model evaluation \cite{katsogiannis2023survey,nan2023enhancing,sun2023sqlprompt}. These advances do not remove an applied design question: which parts of the database context and output contract should be placed in the prompt, and do their effects persist across model backbones?

Schema presentation, value exposure, domain normalization, and answer specification are often changed together. A system may shorten the schema, replace a global value dictionary with question-matched values, add normalization rules, and state SQL-operation requirements in one revised prompt, then attribute any improvement to ``schema selection'' or ``formatting.'' Such labels would be inaccurate here. \masql{} instead audits the two interventions actually executed: a bundled context package and a question-derived composite structural/SQL-operation hint. Each question appears in all four cells, so package effects and their interaction can be estimated without confusing question difficulty with prompt condition.

The structural endpoint is deliberately separated from semantic correctness. A response can return the requested number of projected columns while retrieving incorrect content. We therefore make strict execution equality the primary endpoint and use one common-target projected-column diagnostic in every cell. This diagnostic requires successful execution and equality between the result-column count and a single project-authored target frozen per question; it does not validate row granularity, ordering, or meaning. A useful engineering conclusion must therefore be based on the executed result, not on structural conformity alone.

The revised study also separates canonical evidence from development-visible material. The primary GridDB corpus contains 200 questions, of which 20 are development records and 180 form the factorial evaluation partition. This partition has been used in prior local development and is therefore not described as a newly administered sealed benchmark. Two local, quantized instruction backbones were run under frozen configurations, and independent audit scripts directly re-executed all 1440 predictions. An earlier interrupted Qwen directory is quarantined and excluded from every canonical table.

For external scope, we materialize relational pilots from RTS-GMLC and SimBench. Their schemas and automatically constructed question--SQL candidates provide a realistic test of protocol plumbing, safety checks, and schema portability. They do not yet provide human-reviewed external accuracy: zero of the 91 external candidates have completed the prepared two-reviewer adjudication process. A Qwen diagnostic run over these candidates is retained outside the canonical evidence chain because comparing model outputs with automatic candidate SQL cannot substitute for qualified semantic review.

The study provides five elements. First, it specifies an executed text-to-SQL procedure with explicit gold isolation, one-call generation, parsing, safety validation, and ledger writing. Second, it decomposes two GridDB-tailored prompt packages in a paired $2\times2$ design. Third, it reports two complete local-model runs with hash-bound model snapshots, prompt and data artifacts, failure accounting, and direct SQLite re-execution. Fourth, it states a finite-set inference hierarchy with cluster-level sign flips, family-wise Holm correction, and separately labeled composition sensitivity. Fifth, it adds a prospectively frozen component study of presented value evidence and deterministic candidate selection, alongside a data card, selector audit, and explicit external-validation gate.

The empirical result is narrower than the original architectural expectation. The composite hint increases common-target projected-column conformity for both tested backbones, but none of the nine primary factorial execution tests survives family-wise correction. Presented value evidence satisfies the declared rule for Qwen only, and deterministic candidate selection satisfies it for neither snapshot. Accordingly, \masql{} is presented as an auditable case study, not as proof that every stage independently improves accuracy.

The remainder of the paper reviews text-to-SQL grounding and power-grid data applications, defines the data and framework, specifies the factorial and statistical protocol, reports cell-level and cross-backbone results, discusses operational implications and limitations, and identifies the human and repository gates that remain before submission and external deployment.

\section{Related Work}
\subsection{Text-to-SQL and Cross-Database Evaluation}
Text-to-SQL research has progressed from template and grammar systems to neural parsers and instruction-tuned language models. Spider established a cross-domain, cross-database setting in which train and test databases differ, forcing models to interpret unfamiliar schemas rather than memorize query templates \cite{yu2018spider}. Its difficulty also highlighted the need to evaluate structural decisions such as joins, nesting, aggregation, grouping, and ordering. Later benchmarks and surveys catalogued continuing challenges in schema linking, compositional generalization, ambiguous questions, and realistic database content \cite{katsogiannis2023survey,lee2021kaggledbqa,li2023bird}.

Execution-based evaluation answers a question that string match cannot: whether the predicted query produces the intended result on a particular database state. Exact SQL match can penalize semantically equivalent queries, whereas execution equality can fail to distinguish nonequivalent queries on an insufficiently discriminating database. Applied work should therefore freeze the execution contract, retain the predicted SQL, and state the database boundary. In this study, strict result equality is primary; projected-column conformity and error categories are separate diagnostics. We do not claim semantic equivalence beyond the frozen database instances.

Constrained decoding and execution guidance reduce invalid outputs. PICARD incrementally rejects tokens that cannot form admissible SQL \cite{scholak2021picard}. Execution-guided approaches test candidate queries against a database and use failures or results during selection. \masql{} uses a lighter boundary: the generator is prompted once under a frozen condition, then a deterministic parser and read-only validator classify and execute the output. No gold SQL or gold result is available during generation or candidate selection.

Large language models make prompt context a central design variable. Schema serialization, examples, column descriptions, value samples, and explicit output instructions compete for a finite context budget. Empirical studies show that model performance can depend strongly on representation and demonstration choices \cite{nan2023enhancing,sun2023sqlprompt,pourreza2023dinsql}. Yet combined prompt revisions do not reveal causal contribution. Our factorial design estimates two interventions separately and shows that a prompt feature can improve response conformity more reliably than semantic execution.

\subsection{Schema Linking, Context Selection, and Response Contracts}
Schema linking connects question spans to tables, columns, values, and relationships \cite{wang2020ratsql,lei2020reexamining,liu2022semantic}. A full schema preserves all available elements but may introduce distractors, long-range dependencies, and token cost. Compact context aims to retain question-relevant elements while removing low-relevance structure. This creates a recall--precision trade-off: excluding a needed join key is catastrophic, while retaining unrelated tables may confuse a generator. Deterministic introspection and selection make this trade-off auditable.

Output contracts describe what a response should contain. In text-to-SQL, such guidance can specify projected fields, row granularity, ordering, aggregation, grouping/HAVING, or LIMIT behavior. The intervention tested here is consequently broader than an answer-format hint and is explicitly corpus-tailored. We record only a common-target projected-column indicator independently of execution equality. The two endpoints must not be merged: high column-count conformity shows reception of one structural instruction, not correctness of the returned database content.

Recent domain-oriented systems combine schema retrieval, value grounding, decomposition, and repair, including CHESS and the Applied Sciences DKA-SQL study \cite{talaei2024chess,bian2025dkasql}. DKA-SQL is a direct power-grid text-to-SQL precedent, so the present contribution is not priority of invention. Its published evidence, methods, models, and corpora differ materially from ours, and no official implementation or immutable prompt/code release was located in the literature audit; we therefore make no numerical superiority or reproduction claim. A $2\times2$ design estimates the bundled context-package effect, composite-hint effect, and difference-in-differences interaction. Repeating the same design for two backbones is a sensitivity analysis, not a general model-family study.

\subsection{Power-Grid Databases and AI-Assisted Access}
Power-system datasets mix network topology, asset attributes, time series, costs, constraints, maintenance records, and event narratives. RTS-GMLC provides a reproducible test-system resource with buses, branches, generators, loads, renewable profiles, reserves, and dispatch-related data \cite{barrows2020rts}. SimBench supplies benchmark networks for multiple voltage levels and scenarios \cite{meinecke2020simbench}. Both resources can be transformed into relational databases that exercise selections, joins, aggregation, ranking, and topology-oriented questions.

These public engineering resources are attractive for external validation, but database availability does not create a text-to-SQL benchmark automatically. Natural-language questions and reference SQL must be semantically reviewed, units and tie handling must be specified, and ambiguous projections must be resolved. Automatically generated pairs are useful for building and testing the procedure, yet their agreement with a model output is not human-reviewed accuracy. The present paper treats the external resources accordingly.

Recent work applies language models to grid-domain information extraction, including a semantic-dependency and lexical-embedding RoBERTa design in this journal \cite{meng2023gridroberta}. Relational-provenance research in the same venue further motivates preserving query and source lineage \cite{tang2023provenance}. The central risk is that fluent output can be mistaken for validated engineering reasoning. Text-to-SQL offers a comparatively inspectable interface because the generated query and returned rows can be reviewed. That advantage depends on a read-only execution policy, stable database provenance, and conservative claims about what the execution demonstrates.

\section{Materials and Methods}
\subsection{Task Definition and Evidence Boundary}
Let $x_i$ be a natural-language question, $D_i$ a read-only database, $S_i$ its introspected schema, and $y_i^\star$ a reference query used only by the offline evaluator. For context-package condition $c\in\{0,1\}$ and composite-hint condition $h\in\{0,1\}$, the model produces
\begin{equation}
\widetilde y_{i,c,h}=M(C_{i,c,h};\theta,\rho),
\end{equation}
where $\theta$ is a frozen model snapshot and decoding configuration and $\rho$ is the prompt template. The two executed packages are
\begin{equation}
C_{i,0,h}=P_{\mathrm{full}}(S_i,V)\oplus hH(x_i),\qquad
C_{i,1,h}=P_{\mathrm{compact}}(x_i,S_i,V)\oplus hH(x_i),
\end{equation}
where $P_{\mathrm{full}}$ contains complete eight-table DDL plus a global permitted-value dictionary, whereas $P_{\mathrm{compact}}$ contains question-selected tables/columns, retained joins, matched values, and handcrafted normalization/predicate hints. Thus $c$ is a bundled package factor, not an isolated schema-length intervention. $H$ is a GridDB-tailored composite structural/SQL-operation hint, not a pure formatting hint.

The parser and validator return either one admissible query or a terminal error:
\begin{equation}
\widehat y_{i,c,h}=R(\widetilde y_{i,c,h},D_i).
\end{equation}
$R$ removes presentation wrappers, rejects multiple statements and write-capable statements, checks a single \texttt{SELECT} or \texttt{WITH} form, and executes admissible SQL against a database opened read-only. It never sees $y_i^\star$ or its result while selecting a candidate.

The experiment estimates prompt intervention effects, not a sealed generalization score. GridDB's 180 evaluation records have been exposed during earlier project development; they are held out from the current prompt-construction code but are not described as never-seen data. External candidates are development-visible and automatically generated. These boundaries are carried into the title interpretation, abstract, Results, and Data Availability Statement.

\subsection{\masql{} Processing Pipeline}
Figure~\ref{fig:pipeline} and Algorithm~\ref{alg:pipeline} describe the executed path. It contains no candidate ranking, repair loop, or repeated generation. Gold SQL and gold results enter only after a terminal ledger row has been written.

\caption{Executed \masql{} path. Each backbone makes one generation per question and factorial cell; the offline gold boundary follows terminal ledger writing.}\label{fig:pipeline}

\begin{algorithm}[H]
\caption{Executed one-call factorial pipeline}\label{alg:pipeline}
\begin{algorithmic}[1]
\STATE \textbf{Input:} question $x_i$, read-only SQLite snapshot $D_i$, frozen model $M_b$, cell $(c,h)$.
\STATE Assert that the prompt-path record contains no gold SQL, gold result, or answer field.
\STATE Freeze introspected tables, columns, primary/foreign keys, descriptions, and permitted values.
\IF{$c=0$} \STATE serialize complete DDL and the global value inventory.
\ELSE \STATE tokenize $x_i$; match permitted values; fire frozen synonym, date, numeric, topology, aggregation, and domain-literal rules; select seed schema; expand foreign-key paths to at most six tables; serialize selected schema, joins, matched values, and normalization hints. \ENDIF
\IF{$h=1$} \STATE append the frozen projected-column, row-granularity, ordering, aggregation, grouping/HAVING, projection, and LIMIT instructions derived from $x_i$. \ENDIF
\STATE Serialize the common safety instruction, condition label, question ID, context, and question; hash prompt and context; assert absence of the literal gold SQL.
\STATE Make exactly one deterministic model request; parse the first \texttt{WITH}/\texttt{SELECT} candidate through its first semicolon.
\STATE Require one read-only statement; execute admissible SQL against $D_i$; write raw response, parsed SQL, status, errors, hashes, tokens, latency, and retry count to the terminal ledger.
\STATE Only then compare the executed result with the frozen reference result offline.
\end{algorithmic}
\end{algorithm}

The parser boundary is deliberately narrow: it retains the first candidate through the first semicolon before validation. We therefore claim that the parsed candidate passed the single-statement read-only validator, not that arbitrary later raw-response text was formally proven harmless. Every attempt carries stable question, cell, model, run, prompt, context, database, code, and configuration identifiers.

\subsection{Prompt Packages and Factor Audit}
The full package is constant across questions apart from the question text: all eight-table DDL and a sorted global dictionary drawn from permitted non-ID categorical, date, and text columns. The compact package first matches permitted values, applies frozen corpus-tailored phrase and normalization rules, selects seed tables/columns, expands foreign-key connections to at most six tables, and serializes joins, matched values, and predicate hints. If selection omits a needed element, the model cannot recover it from gold metadata.

The composite hint can specify the expected projected-column count, row granularity, ordering need, \texttt{COUNT}/\texttt{AVG}/\texttt{SUM}/\texttt{MIN}/\texttt{MAX}, \texttt{GROUP BY}/\texttt{HAVING}, exact projection fields, descending order, or \texttt{LIMIT}. Its serialization also differs between full and compact packages. The estimand is therefore the effect of this frozen composite package as actually delivered; it is not the effect of a generic answer-format sentence.

For the representative question ``How many alarmed readings does each asset have?'', F00 contains complete DDL and the global dictionary; F01 adds a two-column, multi-row, ordered \texttt{COUNT(*)} hint. F10 contains six graph-expanded tables, the \texttt{sensor\_readings.asset\_id = assets.asset\_id} join and the normalization \texttt{alarm\_flag = 1}; F11 adds the corresponding two-column, multi-row, ordering and count instructions. Across all 180 questions, question ID, database, common safety instruction, model settings, one-call policy, parser, validator, and offline evaluator are invariant. Prompt-field auditing confirms that F00/F01 always contain full DDL and the global dictionary, F10/F11 always contain selected schema and joins, and the composite hint occurs only in F01/F11. Matched values occur for 162 questions and normalization hints for 170, by construction rather than missing data.

\subsection{Outcomes and Scoring}
Strict execution equality on the frozen database state is
\begin{equation}
z_{i,c,h,b}=\mathbf{1}\!\left[\operatorname{Exec}(\widehat y_{i,c,h,b},D_i)
\equiv \operatorname{Exec}(y_i^\star,D_i)\right],
\end{equation}
where $b$ indexes the backbone. The frozen equivalence contract compares projected values, row multiplicity, ordering when required, null values, and numeric tolerance. Failed parsing, unsafe output, and execution error remain failures in the all-attempt denominator.

The common-target projected-column diagnostic is
\begin{equation}
q_{i,c,h,b}=\mathbf{1}[\widehat y_{i,c,h,b}\text{ executes and }K(\widehat y_{i,c,h,b},D_i)=k_i^\star],
\end{equation}
where $K$ is the number of projected result columns and $k_i^\star$ is one frozen project-authored target applied identically to all four cells and both backbones. The target distribution is 61 one-column, 31 two-column, 57 three-column, and 31 four-column questions. The same project annotation supplies the target exposed by the hint package and the target used by this diagnostic. Therefore $q$ is a direct adherence/manipulation check, not independent corroboration of semantic benefit. This corrects the former condition-dependent diagnostic, which used a one-column default in no-hint cells. We report $\bar z$ and $\bar q$ separately; $q$ neither establishes semantic equivalence nor validates ordering or row granularity.

\subsection{Retrospective Multi-State Reliability Stress Test}
Single-snapshot agreement can accept SQL programs that happen to return the same values on one database state. We therefore constructed a query-blind deterministic stress suite after the canonical predictions had been archived. Stage A materializes 18 hash-bound database states without reading a predicted query: the original snapshot; 14 additional semantic states covering retained clones, attribute rotations, relationship rewiring, numeric and temporal shifts, categorical and boundary witnesses, nulls, anti-joins, isolated parents, topology motifs, and string decoys; and three insertion-order permutations. The first 15 states form the semantic suite. The three physical permutations diagnose order dependence but never enter the semantic logical-AND endpoint.

Two separately executed automated protocol screens examined the metadata for the 114 questions marked as order-sensitive, including all 18 top-$k$ items, without access to model predictions or stress-test outcomes. Both screens found that none combined a sufficiently specific request, metadata record, schema constraint, and gold ordering rule for automatic total-order comparison. All 114 are therefore excluded from the confirmatory automatic analysis; the remaining 66 order-insensitive questions form the finite automatic subset. This conservative screen is not qualified human annotation of question--SQL correctness.

For prediction $j$ and semantic state $s\in\mathcal{S}_{15}$, let $a_{j,s}$ indicate equality between the predicted- and gold-query results under the same value, multiplicity, null, and numeric-tolerance contract. The reliability endpoint is
\begin{equation}
r_j=\prod_{s\in\mathcal{S}_{15}} a_{j,s}.
\end{equation}
Every error remains a failure. Exact denominators are 25,920 atomic executions ($1440\times18$), 7920 primary semantic rows ($528\times15$), and 16,416 held diagnostic rows ($912\times18$). Before output was committed, a T0 gate had to reproduce all 1440 canonical labels. The same three within-backbone contrasts and three cross-backbone modifiers are evaluated with $m=r$ on this 66-question subset, as a third and distinct nine-test Holm family. The frozen release uses 100,000 cluster sign flips and 20,000 cluster bootstrap draws. Its base seed is 20260805; for zero-based family index $i$, sign-flip and bootstrap seeds are respectively base$+1000+i$ and base$+10000+i$. Because the eligible subset has only 12 normalized-SQL clusters, an exact sensitivity analysis enumerates all $2^{12}=4096$ sign assignments and supplies the displayed raw $p$-values; the Holm conclusion is unchanged. Cluster sizes are 18, 15, 12, 8, 6, and seven singletons (range 1--18; median 1; 59/66 questions in the five largest clusters). This imbalance motivates composition-sensitivity rather than population-confidence intervals. Because the test is retrospective and gold-query based, it is described as automated multi-state agreement, not semantic certification.

\subsection{Statistical Analysis}
For outcome $m\in\{z,q\}$, the compact/domain-grounded package main effect, composite-hint main effect, and interaction are
\begin{align}
\Delta_{C,b}^{(m)}&=\tfrac12[(\bar m_{1,0,b}-\bar m_{0,0,b})+
(\bar m_{1,1,b}-\bar m_{0,1,b})],\\
\Delta_{H,b}^{(m)}&=\tfrac12[(\bar m_{0,1,b}-\bar m_{0,0,b})+
(\bar m_{1,1,b}-\bar m_{1,0,b})],\\
\Delta_{CH,b}^{(m)}&=(\bar m_{1,1,b}-\bar m_{1,0,b})-
(\bar m_{0,1,b}-\bar m_{0,0,b}).
\end{align}
A positive context effect favors the compact/domain-grounded bundle; a positive hint effect favors the composite hint. The interaction is the difference between hint effects under the two packages.

All point estimates are exact, equally question-weighted contrasts on the finite frozen set. The normalized-gold-SQL mapping supplies a dependence proxy with 70 groups, 58 singletons, and a maximum group size of 19; these groups are not claimed to be authoring templates or a probability sample. For each core contrast, 100,000 Monte Carlo sign flips reverse every aligned difference within a group together. The plus-one correction prevents zero Monte Carlo $p$-values \cite{phipson2010permutation}. The primary family contains exactly nine execution tests: the three factorial effects for each backbone and three Granite-minus-Qwen modifiers. Holm's procedure controls this family \cite{holm1979simple}. A separate secondary family applies the same nine-test structure to common-target adherence, explicitly as a manipulation check. This analysis hierarchy was fixed on 5 August 2026 after the initial factorial results had been inspected; it is therefore not presented as preregistration.

We also make 20,000 paired group-bootstrap draws, retaining every question and all aligned cells/backbones in a sampled group \cite{efron1979bootstrap,cameron2008bootstrap}. Their percentile limits are called \emph{composition-sensitivity intervals}: they describe sensitivity to the observed group mix and are not confidence intervals for an unstated external question population. A coarser 39-group difficulty-by-feature proxy supplies a second composition analysis. Both mappings preserve question-level weighting. Cluster sign flips rely on an explicit within-group symmetry boundary \cite{canay2017randomization}. Question-level McNemar outputs remain descriptive because they ignore the grouped dependence \cite{mcnemar1947note}.

Cross-backbone modifiers are calculated from question-aligned outcome differences before dependence-group resampling. For example,
\begin{equation}
\Delta_{B\times H}^{(m)}=\Delta_{H,\mathrm{Granite}}^{(m)}
-\Delta_{H,\mathrm{Qwen}}^{(m)}.
\end{equation}
The three-way modifier analogously compares the two context--hint interactions. These estimands describe the two tested snapshots only.

\subsection{Prospectively Frozen Component Experiments}
Because the factorial interventions bundled several prompt elements, we specified a separate component protocol before generating its formal outputs. E1 isolates \emph{presented value evidence}. Its V0 and V1 prompts share the question, selected schema, join paths, composite structural hint, model settings, and candidate request; V1 alone contains exact matched values and question-derived normalization-value evidence. This is a presentation ablation, not a pure retrieval test. The intervention changes the prompt for 170 questions in 61 normalized-SQL groups; ten byte-identical cases receive V1 only and are excluded from E1.

E2 evaluates a deterministic, reference-answer-independent candidate selector on all 180 V1 questions. Each response requests up to three candidates. The frozen ranker uses only read-only safety, SQLite executability, output-column shape, ordering, non-empty execution, and presented-value coverage; it seals its choice before gold SQL or results are loaded. E2 compares the selected candidate with the first candidate. Rescue, harm, selection-change, and oracle-at-three counts are descriptive, and oracle-at-three is never a deployable result. There is no repair call.

E4 records paired telemetry for consecutive V0/V1 calls under deterministic balanced AB/BA order. The formal schedule contains 350 scored calls per backbone---170 V0/V1 pairs plus ten V1-only calls---or 700 scored calls total, after four unscored warm-up calls per backbone. Temperature, seed, backend, and loaded snapshot match within each backbone; maximum output length is 600 tokens. An input whitelist excludes gold SQL, required literals, annotated answer fields, and results before prompt construction.

E1 and E2 report question-weighted execution-equality differences, 20,000 group-bootstrap composition intervals, and 100,000 group sign flips. Holm correction is applied to two tests within E1 and separately to two tests within E2. The two Granite-minus-Qwen modifiers form a secondary two-test family. Positive component efficacy requires a positive estimate, an interval excluding zero, and adjusted $p<0.05$. The protocol does not define one successful backbone as replication. E4 is estimation-focused; because the required no-competing-process/thermal attestation is missing, latency remains diagnostic even though retry incidence was zero. Model-reported token differences remain reportable.

\section{Discussion}
\subsection{What the Evidence Supports}
The clearest factorial result is the composite hint on the common-target projected-column manipulation check. Both backbones show increases larger than 0.35 and survive the separate secondary family. Explicit structural and SQL-operation instructions therefore change projected-column adherence in this bounded experiment. Because the hint also contains aggregation, grouping, projection, ordering, and limit rules, this result cannot be reduced to generic formatting advice or treated as independent semantic validation.

Factorial execution is more conditional. All nine primary tests fail Holm correction, even where composition-sensitivity intervals exclude zero. This divergence is not contradictory: randomization tests implement the predeclared finite-set decision rule, whereas the intervals show how estimates change when the empirical group composition is reweighted. Neither is evidence from a random sample of databases or questions.

The multi-state stress test is consistent with the negative factorial conclusion. Requiring one archived SQL program to agree with the gold query across 15 constructed states reduces every cell's success count relative to or equal to its T0 count, and no factorial suite effect meets the declared evidence rule. The result indicates that a single frozen snapshot can overstate reliability for some predictions. It does not prove full semantic equivalence: the states are deterministic constructions from one small database, the automatic subset covers only 12 normalized-SQL clusters, and all order-sensitive questions remain outside the primary suite.

The compact/domain-grounded package does not show a uniformly positive independent effect. For Qwen its execution main effect is negative with an upper interval endpoint at zero; for Granite it is small and uncertain. The package is substantially shorter, but it simultaneously changes schema coverage, value presentation, join serialization, and normalization. It is therefore neither a pure schema-selection ablation nor evidence that shorter prompts improve accuracy.

The prospective component results refine but do not generalize the architectural interpretation. Presented value evidence passes the efficacy rule for Qwen only; its zero Granite estimate and unsupported modifier preclude a replicated or universal value-grounding claim. The deterministic selector yields rescues for both backbones but does not pass either adjusted test. Deployment teams should therefore validate the complete model--prompt--database combination under execution rather than assume that a stage label guarantees benefit.

\subsection{Projected Columns versus Semantic Correctness}
The gap between the common-target diagnostic and execution equality is a warning against surface-only evaluation. In Qwen F01, projected-column conformity is 0.9667 while execution equality is 0.7167. In Granite F01 the corresponding values are 0.8778 and 0.5556. A model can return the requested number of columns yet select the wrong table, field, filter, join, or aggregation.

The projected-column diagnostic remains useful because it localizes one interface failure and shows that an intervention is received. It should be reported next to, not substituted for, execution. Row granularity and ordering were present in prompts but are not validated by this endpoint. Where a database state is insufficiently discriminating, manual semantic review or test-database augmentation is also needed.

\subsection{Implications for Power-Grid Data Access}
An operational interface should expose the generated SQL, database snapshot, schema context, and execution status. Read-only enforcement prevents accidental mutation but does not prevent a semantically wrong query from returning plausible rows. High-consequence decisions therefore require review of both the SQL and the source data.

The immediate beneficiaries of the prototype are maintenance engineers, asset-data analysts, and query reviewers retrieving inspection, alarm, or work-order records for human review. The system is not designed to issue protection actions, dispatch instructions, or autonomous maintenance decisions; it only proposes a read-only query whose SQL and returned rows remain inspectable.

The external diagnostic is useful precisely because it fails visibly. Missing-column errors indicate that the model inferred familiar field names rather than grounding to the actual schema. Prompt repair should target these mismatches, then be evaluated on new or sealed items rather than repeatedly optimizing against the same 91 visible candidates.

RTS-GMLC and SimBench broaden the engineering structures represented in the project: topology, generation, constraints, time series, and network elements. Their inclusion does not by itself validate maintenance-database generalization. A credible external benchmark needs domain experts to verify terminology, units, expected projections, acceptable equivalences, and tie rules.

\subsection{Reproducibility and Negative Results}
The quarantined Qwen incident demonstrates why result directories need immutable identity and process accounting. A directory containing more generations than the registered Cartesian design is not repaired by truncating it. The clean rerun provides a separate evidence chain, and the audit confirms that the contaminated output contributed no canonical row.

Hash-bound artifacts reduce transcription and provenance errors. They do not make an exposed test partition sealed, resolve a missing data license, or turn automatic candidates into human labels. Reproducibility and evidential validity are related but distinct.

The compact/domain-grounded package does not show an independent execution benefit under the declared rule. The stage remains available for future selectors, but the present data do not support assigning it a separate positive effect. The prospective E2 selector likewise fails its adjusted decision rule despite descriptive rescues. E1 supports presented value evidence for one snapshot only. BIRD model baselines remain unexecuted, and the E4 latency records remain diagnostic rather than comparative-efficiency evidence.

\subsection{Limitations}
The primary corpus is one synthetic 8-table, 98-row maintenance-oriented database and only 180 evaluation questions. Questions map to 70 normalized-SQL dependence-proxy groups, 58 of them singletons; grouped procedures respect this mapping, but it is not an authoring-template identifier and the corpus cannot represent the diversity of production schemas, permissions, missing values, units, or data quality.

The evaluation partition was visible in earlier development. Gold fields are excluded from prompts and the formal runs are frozen, but prior analyst exposure prevents a sealed-test claim. The two model snapshots use Q4\_K\_M quantization and one llama.cpp revision. Results may differ for full-precision weights, alternative quantization, other runtimes, stochastic decoding, or hosted models.

Only one generation is made per factorial prompt and one formal response per component condition. Temperature zero and fixed runtime settings improve repeatability, but they do not quantify decoding variance or server nondeterminism. The second backbone is sensitivity analysis, not replication, and no cross-backbone component effect satisfies a replication rule. Multi-run inference would require a prospectively frozen hierarchical analysis and materially greater compute.

Execution equality is database-state dependent. Different SQL statements may agree accidentally on the current data, and minor projection differences may be judged wrong under the strict contract. The contract is intentionally fixed, yet no single automatic metric captures every notion of semantic equivalence.

The 15-state suite addresses accidental equality only within its constructed witnesses. It was designed retrospectively, does not constitute an independent human semantic audit, and cannot certify behavior on unconstructed values or schemas. Two prediction-blinded machine-assisted protocol audits excluded all 114 order-sensitive questions; qualified domain reviewers must still resolve intended ordering, ties, units, and result granularity before those questions support semantic claims.

E4 records paired telemetry under a frozen order, but the required efficiency attestation is missing. Token deltas remain valid descriptive outputs; latency and throughput are diagnostic, and no energy or memory measurement supports deployment-efficiency claims. A confirmatory efficiency study requires independently verified process isolation, thermal state, common hardware, and separate generation/database timing.

External candidates have not completed human review. Their automatic references and the Qwen diagnostic are development evidence only. No claim of RTS-GMLC or SimBench accuracy, cross-database generalization, or operational readiness follows from them.

GridDB redistribution permission is unresolved, and derived RTS-GMLC and SimBench artifacts have source-specific notice and database-license obligations. A public artifact release must undergo license review before deposit in a permanent repository.

\subsection{Future Work}
The immediate external study should complete two independent qualified reviews of all 91 development-visible candidates, retain disagreements, and adjudicate them under the frozen manual. The resulting evidence would be human-reviewed but still unsealed. A separate confirmatory set should be newly authored or deeply rewritten after the prompt and schema-repair work is frozen, screened for overlap, withheld by a custodian, and executed once without post hoc exclusions.

The compact/domain-grounded builder should be redesigned around reference-free coverage safeguards. Candidate columns and relationships could be accompanied by explicit connectivity checks and a fallback to the full package when join paths appear incomplete. The observed offline table/column recall cannot be used online because it depends on gold-required fields. Any replacement safeguard constitutes a new intervention and must be evaluated prospectively.

The completed E2 replay should be followed only by a newly frozen selector revision; tuning against its visible rescues would make the present set development data. Efficiency confirmation requires controlled warm and cold runs, common hardware, token accounting, resident and accelerator memory, energy where possible, and separate model-generation and SQL-execution latency.

After explicit human launch authorization, the technically frozen BIRD Mini-Dev protocol could add transparent direct, decomposition, schema-selection, and bounded execution-feedback baselines on the same two snapshots. Its 500/500 SQLite 3.40.1 gold-query preflight is a mechanical gate, not model evidence. Until the registered 5000 calls and independent post-run audit are complete, no BIRD comparison is available. The study must not be described as DKASQL reproduction because no official implementation was found. Additional backbones, sizes, quantizations, decoding settings, and repeated runs would test whether the finite-set execution contrasts persist.

\section{Conclusions}
\masql{} provides an auditable case study of context grounding for power-grid text-to-SQL. Across two local backbones subjected to repeated artifact verification, a GridDB-tailored composite structural/SQL-operation hint improves a common-target projected-column manipulation check, but none of nine primary factorial execution tests survives family-wise correction. The compact/domain-grounded package does not show an independent positive execution effect. In the separate 700-call component study, presented value evidence improves Qwen execution under the frozen rule but not Granite execution; deterministic candidate selection meets the rule for neither snapshot. A retrospective 15-state logical-AND stress test likewise yields no effect that meets the nine-test reliability rule, while exposing lower agreement than the original snapshot in every cell.

The practical conclusion is not that one prompt recipe or component universally wins. Model, schema/value context, handcrafted normalization, operation guidance, and candidate selection form a coupled system that must be evaluated with database execution. Hash-bound ledgers, explicit finite-set families, multi-state witnesses, composition sensitivity, candidate choices fixed before gold access, and negative results make this bounded conclusion reproducible. External RTS-GMLC and SimBench work remains a mechanically validated development pilot until qualified reviewers assess the question--SQL pairs; sealed evidence additionally requires a new withheld set and registered execution. BIRD remains an unexecuted protocol despite its completed technical freeze and gold-query preflight.
