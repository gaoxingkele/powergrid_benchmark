## 1. 总体判断与修订目标

当前稿件不存在已经被证实的算法错误，也具备确定性、来源可追溯和负向结果报告诚实等优点；但核心主张与核心证据之间仍有明显缺口。论文声称结构感知选择能够更好地组织维护型技术报告，并具有工程导航价值，但现有实验主要使用 ROUGE-L 和冗余度评价，尚未直接验证角色、关系、路径、来源忠实度、遗漏风险或真实使用效用。同时，Full C²GES 的输出长度比 Semantic-MMR 和 TextRank 长约 54%--63%，不同系统的调参机会不对称，路径项消融还受到权重尺度变化的干扰。因此，当前结果只能支持“该框架能够以确定且可审计的方式运行，并揭示了路径项未产生预期收益”，不能支持“该方法已经在公平比较下优于基线”或“已经改善了工程决策”。

本轮修订应达到两个目标。第一，重建全文的主张层级，使标题、摘要、引言、研究问题、结果、讨论和结论只陈述已有证据真正支持的内容。第二，通过匹配输出预算、平衡调参、干净消融、结构有效性标注、系列级统计和外部或专家验证，补上方法主张所需的直接证据。只有第二类工作完成后，才能恢复较强的性能或应用价值表述。

## 2. 文本部分的修改意见

文本修订的原则是“证据先行、主张后置”。对于 C1--C6，不应把“承认局限性”当作完成修订；局限性段落只能界定当前结论，不能替代新实验。正文应先保持保守版本，待补充实验完成后再根据结果提高或继续降低主张强度。

### 2.1 标题、摘要与关键词

**需要修改的内容：**

1. 检查标题是否暗示 C²GES 已经获得经过验证的工程效用或稳定优越性。如果标题使用了容易被理解为效果结论的词，例如 “effective”“improved maintenance decision support” 或无条件的 “structure-aware superiority”，应改为描述研究对象和框架属性的标题，例如突出 deterministic、source-linked、diagnostic evaluation，而不是突出未经直接验证的效果。
2. 摘要的结果顺序应固定为：数据与任务范围；strict variant 的最高观测结果；Full C²GES 的绝对结果；与基线比较中的输出长度和调参限制；路径项负向结论；能够支持的最终贡献。
3. 摘要中禁止把“路径项改变了排序或选择”写成“路径项有效”。组件处于活跃状态只证明它会产生影响，不证明影响方向正确。
4. 如果完成匹配预算和专家实验，应在摘要中报告效应量、置信区间和直接结构/效用指标；如果未完成，则摘要必须继续使用 descriptive comparison、proxy evaluation、does not establish 等限定。

**为什么要修改：** 摘要决定编辑和审稿人如何理解论文的证据等级。当前最容易受到攻击的点不是结果为负，而是主张可能超过结果。把负向结果和比较限制前置，可以将论文定位为透明、可审计的应用研究，而不是一次被不公平比较支撑的性能宣称。

**验收标准：** 摘要中的每一个效果性动词都能在结果表或人工评价中找到直接证据；不再出现以 equal-unit、unequal-word 结果支持公平优越性的句子；strict variant 的观测优势和路径项负向结果均未被弱化。

### 2.2 引言、研究问题与贡献定位

**需要修改的内容：**

1. 将研究动机从“已有摘要指标不足，因此结构方法必然更好”改为可检验的逻辑：维护型报告包含不同信息角色和跨段关系，传统词汇指标可能无法覆盖这些需求，因此需要同时评估词汇覆盖、结构有效性、来源忠实度和使用效用。
2. 重写研究问题，使每个问题都对应可执行的实验：
   - **RQ1：** 在相同候选单元和相同词数或 Token 预算下，C²GES 与经过平衡调参的基线在覆盖、冗余和来源忠实度上如何比较？
   - **RQ2：** 角色预留、类型边、图显著性和路径项分别贡献了什么，是否存在交互作用？
   - **RQ3：** 自动分配的角色、关系和路径是否得到人工支持，其精度、覆盖率和一致性如何？
   - **RQ4（仅在完成专家实验时保留）：** 结构化输出是否改善专家定位原因、影响和缓解措施的正确率、用时或遗漏风险？
3. 将贡献段改为连续的论证层级：主要贡献是确定、可追溯的选择与诊断框架；第二层是匹配预算和结构标注的评价协议；第三层是对路径项的实证结论，包括可能的负向结果。不要继续把未验证的路径项写成最核心创新成果。
4. 引言末尾明确研究边界：当前 NERC 报告属于 maintenance-oriented technical-report proxy，而非真实工单或现场维护记录。

**为什么要修改：** 当前最大的一致性问题是引言承诺了结构和工程价值，而实验只回答了词汇重合与冗余。修改 RQ 后，论文的每项贡献都必须在结果部分有一张表、一个指标或一个明确的负向结论与之对应，从结构上消除“提出了但没有验证”的问题。

**验收标准：** 所有 RQ 都能在方法和结果中找到一一对应的小节；没有任何贡献只能由未来工作支撑；若专家实验没有完成，RQ4 和相关贡献应删除而不是保留为愿景性陈述。

### 2.3 相关工作与基线定位

**需要修改的内容：**

1. 按方法家族而非按论文罗列相关工作：位置/中心性方法、图排序方法、语义多样性方法、长文档摘要方法、角色或事件结构方法、来源可追溯方法。
2. 增加一张方法定位表，列出候选单元、长度约束、结构表示、是否需要训练、是否保留来源、是否支持角色/关系审计及本研究采用的实现版本。
3. 对 Semantic-MMR、TextRank 和新增强基线说明版本、实现、搜索空间、开发集选择规则及为何具有可比性。不得只写“采用默认设置”。
4. 避免绝对新颖性表述。若声称“首次”或“尚无工作”，必须有可追踪的检索范围和最接近工作；否则改为“在本文检索范围内”或直接说明与邻近方法的差异。

**为什么要修改：** Applied Sciences 审稿人通常不会要求方法必须有复杂数学推导，但会要求应用比较具有现实代表性。如果基线显得过弱或调参不公平，任何数值优势都会失去说服力。

**验收标准：** 每个主要基线都有版本和调参信息；相关工作能够说明 C²GES 的实际增量是“可审计结构与诊断协议”，而不是依靠模糊的新颖性宣称。

### 2.4 方法部分

#### 2.4.1 数据、划分与独立性单位

应增加报告系列定义、每个系列包含的文档数、主题/年份分布，以及开发集和测试集是否共享系列。新的确认性实验必须按“报告系列”分组划分，禁止同一系列同时进入开发集和测试集。应明确当前 15 份测试报告约对应 10 个系列，并解释后续统计为何以系列为聚类单位。

**原因：** 同一系列报告往往共享模板、术语和事件背景，将其视为完全独立样本会使置信区间过窄，并夸大显著性。

#### 2.4.2 候选单元与布局处理

应精确定义“candidate unit”而不是笼统称为 sentence。报告标题、表格、项目符号、跨行单元和页眉页脚需要单独规则。报告以下诊断：单元总数、词数/WordPiece 长度分布、超过编码器上限的比例、表格型单元比例、标题融合比例以及被过滤比例。若保留融合单元，应将其称为 textual unit，并说明为什么该粒度适合比较。

**原因：** 当前存在大量超过 100 词的单元和表格型单元，选择五个“单元”并不等价于选择五个句子。候选粒度差异会同时影响输出长度、嵌入质量、ROUGE 和冗余度，是 RQ1 的基础混杂因素。

#### 2.4.3 嵌入模型与截断

写明 `all-MiniLM-L6-v2` 的精确模型版本或修订号、tokenizer、最大输入长度、padding/truncation 参数和超长单元处理方式。不得仅写模型名称。若采用分块池化或长上下文编码器，应给出确定性聚合规则。

**原因：** 默认截断可能使长候选单元后半部分完全不参与相似度计算，导致 Semantic-MMR 和基于嵌入的组件比较失真。

#### 2.4.4 调参与协议冻结

新增“Protocol freeze”段落，区分探索性旧实验和确认性新实验。列出每个系统的超参数搜索空间、总配置数、选择指标、并列处理规则、随机种子和开发集。新留出集必须在这些选择冻结后才能打开。

**原因：** Full 搜索 144 个配置，而基线固定参数时，观察到的差异混合了方法差异和调参机会差异。冻结协议还可以防止在看过测试结果后继续修改方法造成隐性测试集过拟合。

#### 2.4.5 消融定义

将 strict variant 明确称为“未归一化 coefficient-removal comparison”，并增加归一化版本。每个消融必须只改变一个因素；删除某个正向项后，要么归一化剩余正向项，要么同步缩放冗余惩罚，使整体尺度可比。方法中预先定义主效应和交互效应，而不是在结果出现后选择解释。

**原因：** 当前 strict 变体不仅删除了 0.15 的路径权重，也使固定冗余惩罚的相对影响提高约 17.6%，因此不能把 Full 与 strict 的差异全部归因于路径信息。

#### 2.4.6 人工评价与统计方案

人工标注需要给出标注对象、判定准则、不可判定选项、标注者资格、盲法、培训轮次、分歧仲裁和一致性指标。统计方案应预先指定主要终点、聚类单位、置信区间方法、多重比较校正和效应量。

**原因：** 结构正确性和工程效用不能由 ROUGE 代理。没有明确协议的少量主观示例也不足以构成证据。

### 2.5 实验结果部分

**建议重组顺序：**

1. 数据和候选单元诊断，包括长度、布局类型和截断比例。
2. 相同词数/Token 预算下的主要比较；原有相同单元数结果降为补充分析。
3. 平衡调参后的基线比较，并同时报告每个系统的实际输出长度。
4. 干净的组件消融和交互分析。
5. 人工结构有效性结果。
6. 专家效用或外部数据结果。
7. 系列级稳健性与误差分析。

所有主要表格应报告逐系统均值、配对差异、95% 置信区间和效应量。p 值只作为补充，不应成为唯一判断依据。原先基于 15 份报告逐报告配对检验的结果可保留为探索性分析，但必须与系列级结果分开，不得继续作为唯一的确认性显著性证据。

**为什么要修改：** 结果顺序应从评价有效性到性能结论逐层展开。先展示候选和预算是否公平，再展示系统差异，可以避免审稿人认为作者在用更长输出换取更高 ROUGE。

**验收标准：** 每个主结果表都有长度列和不确定性；相同单元数与相同词数结果不混写；报告系列级结论后再讨论逐报告结果；负向结果没有被隐藏到附录。

### 2.6 讨论、局限性与结论

**需要修改的内容：**

1. 按 RQ 顺序回答，不要重新描述所有表格。每段先给出结论，再说明证据和边界。
2. 将“框架价值”和“路径组件价值”分开。即使路径项继续表现为负，确定性、来源链接和结构诊断仍可能构成独立贡献；但不得把框架可运行性转化为组件有效性。
3. 对路径项给出机制层面的解释假设，例如稀疏图、错误关系、远距离路径放大噪声或权重尺度耦合，但必须标注为假设，并由消融或误差分析检验。
4. 将 external validity、construct validity、statistical conclusion validity 和 implementation reproducibility 分开写，避免把所有限制堆在一个泛化段落中。
5. 若没有真实维护数据或专家任务实验，结论只能声称对 maintenance-oriented technical reports 的代理验证，不能推广到现场维护决策、故障诊断质量或安全性改善。
6. 若新实验仍显示路径项无益，应在结论中直接说明该项不应作为性能增强模块，并将其定位为被证伪的设计假设或需要重新设计的诊断组件。

**为什么要修改：** 负向结果本身不是致命问题；真正致命的是仍用正向语言包装负向组件。清楚拆分框架贡献和组件结论，能够保留论文的社区价值，也减少审稿人对过度宣传的质疑。

### 2.7 可复现性、数据声明和生成式 AI 声明

**需要修改的内容：**

1. 提供从干净环境开始的安装命令和依赖文件，统一 Python 版本与包版本；确保 `rouge_score` 等评测依赖被显式安装。
2. 修正测试发现，使 `test_v031_repair` 中的测试被正常收集；在干净环境中报告完整测试数量和结果。
3. 删除硬编码模型路径，改为配置项或自动下载，并记录模型修订号及文件哈希。
4. 修复构建器对缺失 source manifest 的假设，提供可用的输入清单、下载/构建流程、数据许可说明和中间产物哈希。
5. 核对补充材料中被引用的 `transferable/`、ledgers 和其他目录是否真实存在；不存在的引用必须删除或补齐。
6. Data Availability Statement 应精确区分可公开原始报告、处理后数据、人工标注、代码和受许可限制的数据。
7. 在投稿前依据 *Applied Sciences*/MDPI 当时有效的政策核对生成式 AI 声明，写明具体工具、版本、用途、人工核验责任，并避免笼统的“AI assisted writing”表述。

**为什么要修改：** 应用型论文的价值高度依赖可运行性。当前包在既有环境中出现一项导入错误，部分测试未被发现，会削弱“确定性和可复现”的核心定位。

**验收标准：** 在全新环境中仅按 README 可生成主要结果表；完整测试全部收集并通过；论文、README 和补充材料中的文件名、数量、哈希和路径一致。

### 2.8 图表和补充材料

主文建议保留以下结果载体：数据与布局诊断表、匹配预算主结果表、干净消融表、人工结构有效性表、专家/外部验证表、系列级稳健性图。原有大量实现细节、完整搜索网格和逐报告结果可移至补充材料。流程图应显式标出候选切分、角色预测、图构建、来源链接和选择预算，避免给人“路径项等于整个框架”的印象。

## 3. 实验部分的补充意见

### 3.1 实验前置门槛：冻结新版本与确认性协议

在运行新测试集前建立 C²GES v2.1 或等价的新版本标签，冻结候选切分、系统公式、预算、调参空间、主要终点、统计方法和排除标准。已经看过结果的 15 份报告只能作为探索性或开发性证据；若继续对其调参，不能再称其为未见测试集。

**为什么必须先做：** 后续实验很多，若边看测试结果边调整规则，最终高分可能来自反复适配而非泛化能力。协议冻结是后续所有确认性结论的可信度基础。

**最低产出：** 一份带日期和版本号的 protocol 文件、数据系列清单、主终点声明、所有系统搜索空间及代码提交哈希。

### 3.2 E1：布局感知的候选单元重建与质量审计（P1）

**目的：** 消除长表格、标题融合和跨行单元对系统比较的基础性污染。

**设计：**

- 将普通句子、标题、项目符号、表格行/表格块、图注和页眉页脚分型处理。
- 对表格采用结构保留的线性化或独立表格单元，禁止与相邻正文无规则拼接。
- 对超过模型输入上限的单元使用确定性切分或分块聚合，不能静默截断。
- 从不同报告类型中分层抽样候选单元进行人工审计，至少检查边界正确性、语义完整性、布局类型和来源定位。

**主要指标：** 边界正确率、语义完整率、各类型占比、词数和 WordPiece 分布、超长比例、来源定位成功率。

**为什么要做：** 若候选单元本身不是可比较的语义单位，后续任何系统排序和 ROUGE 差异都难以解释。

**通过标准：** 不再存在静默截断；异常长单元和表格融合显著减少；人工审计规则、样本和错误案例均可公开复核。

### 3.3 E2：匹配词数/Token 预算的主要比较（P1）

**目的：** 判断 Full C²GES 的差异是否来自结构选择，而不是来自输出更长。

**设计：**

- 所有系统共享同一候选集合、过滤规则和来源文本。
- 预先设置至少两个预算档位。预算可依据实际应用需要确定，也可围绕现有输出长度中位数设定；主分析必须使用词数或 Token 数，而不是固定单元数。
- 各系统在预算内选择完整单元。若最后一个单元使预算溢出，使用对所有系统相同的确定性策略，不允许只对某一系统截短文本。
- 同时保留 `K=5`、`K=10` 等固定单元数结果作为敏感性分析，不再作为主性能结论。

**主要指标：** ROUGE-L、冗余度、实际词数/Token、来源忠实度，以及 E6 中的结构指标。报告配对差异、95% 聚类置信区间和效应量。

**为什么要做：** 当前 Full 输出长 54%--63%，ROUGE 提升无法与覆盖机会增加分离。匹配预算是恢复 RQ1 可解释性的最低要求。

**决策门槛：** 若优势在匹配预算后消失，应删除“优于基线”的主张，将结果解释为不同内容分配策略；若优势保留，也必须结合结构和忠实度指标判断其实际意义。

### 3.4 E3：嵌入长度与截断敏感性实验（P1）

**目的：** 量化 `all-MiniLM-L6-v2` 输入截断对 Semantic-MMR 和 C²GES 语义组件的影响。

**设计：**

- 统计每个候选的 WordPiece 长度及超过模型上限的比例。
- 比较至少三种处理：当前默认处理、显式截断、确定性分块后池化；如资源允许，再加入适合长输入的编码器作为敏感性分析。
- 对不同布局类型分别报告差异，特别关注表格和长项目符号。

**主要指标：** 候选向量相似度变化、最终选择重合率、ROUGE/冗余变化、人工来源忠实度变化。

**为什么要做：** 如果超长候选后半部分未被编码，系统可能错误估计相关性和冗余；这会同时影响方法和基线，不能被视为无关实现细节。

### 3.5 E4：平衡调参和强基线比较（P1）

**目的：** 将算法差异与调参机会差异分离。

**设计：**

- Full、strict、Semantic-MMR、TextRank 及新增基线使用同一开发集和系列级划分。
- 为每个可调系统分配相近数量的有效配置或相近计算预算，公开所有搜索空间和选择规则。
- 基线至少包含位置型基线、中心性/图排序基线、语义多样性基线和一个适用于长技术文档的较强摘要/选择方法。若采用 MCHES、GraphLSS 或其他邻近方法，应确认任务、代码和输入粒度真正可比；不可仅因名称接近而加入。
- 报告默认参数结果与调优结果，防止调优收益被误写为算法收益。

**主要指标：** 匹配预算下的主要评价指标、开发到测试的性能变化、每个系统的搜索成本与稳定性。

**为什么要做：** Full 的 144 配置搜索相对于固定系数或默认参数基线构成明显不对称。没有平衡调参，审稿人无法判断优势来自方法还是实验资源。

**通过标准：** 每个主要基线的调参预算和选择依据均可审计；结论对默认/调优两种设置不发生未经解释的反转。

### 3.6 E5：路径项及关键组件的干净因子消融（P1）

**目的：** 判断当前负向结果来自路径思想本身、权重尺度、图构建误差还是组件交互。

**建议因素：**

- 角色预留：开启/关闭。
- 类型边：typed/untyped/no edge type。
- 图显著性：开启/关闭。
- 路径项：开启/关闭。
- 路径删除后的权重处理：未归一化/正向项归一化/同步缩放冗余惩罚。
- 路径长度或视野：短路径/当前设置/限制远距离路径。

应先运行最小的主效应设计，再针对有证据的交互做扩展，避免无约束地枚举所有组合。至少需要比较：Full、当前 strict、归一化 strict、仅路径项、无角色预留、无类型边、无图显著性。对所有变体使用相同预算和冻结参数。

**主要指标：** 主要性能指标、选择集合变化、结构人工精度、路径支持率及跨系列稳定性。

**为什么要做：** 当前 zero path weight 在开发集留一分析中 12/12 出现，Full 相对 strict 的差值约为 -0.003332 和 -0.003360，但 strict 同时改变了总分尺度。干净消融才能回答“路径信息无效”还是“当前集成方式无效”。

**决策门槛：** 若归一化后路径项仍稳定为负，应从主性能模块中移除或重新设计；若只在特定报告类型有效，应改为条件性组件并明确适用范围，不能继续作为普适增强项。

### 3.7 E6：结构有效性与来源忠实度人工标注（P1）

**目的：** 直接验证论文真正声称的角色、关系、路径和可追溯性，而不是继续依赖 ROUGE 代理。

**标注任务：**

1. 候选角色是否正确，并允许“多角色”和“不可判定”。
2. 类型边是否被原文明确或合理支持。
3. 路径中的每一跳及完整路径是否成立。
4. 选中单元是否忠实于来源，source span 是否准确。
5. 输出是否遗漏关键原因、影响、缓解措施或安全相关信息。

**采样与人员：** 从不同系列、不同布局和不同系统输出中分层抽样。建议至少由 2--3 名独立标注者完成；标注者应具备电力系统、可靠性报告或相关技术文档分析经验。具体样本量应在小规模试标后依据目标置信区间或功效分析确定。若资源有限，可先完成约 300 个候选单元、150 条边和 100 条路径的验证，但必须把它定位为最低规模诊断，而非充分的普适验证。

**主要指标：** 各角色 precision/recall/F1、边和路径支持率、source-span accuracy、关键遗漏率、Cohen's kappa 或 Krippendorff's alpha，以及分歧类型。

**为什么要做：** 这是弥补 C1 的核心实验。如果路径的人工支持率不高，即使 ROUGE 上升也不能证明结构建模有效；相反，若人工结构精度高但 ROUGE 无提升，论文可以合理主张其价值体现在可审计结构而非词汇重合。

**通过标准：** 标注协议、匿名样本、分歧规则和一致性均被报告；结论根据置信区间而非少数成功案例制定。

### 3.8 E7：专家任务效用研究（P1/P2，取决于论文是否保留应用效用主张）

**目的：** 验证结构化输出是否实际帮助读者定位工程信息，并检查是否增加危险遗漏。

**设计：**

- 采用盲法、随机化、被试内或平衡交叉设计，比较 Full/最佳消融/强基线。
- 任务至少包括定位根因、识别影响范围、找到缓解措施、追溯来源证据和判断是否存在关键信息遗漏。
- 先进行 6--8 人试点以估计方差和任务时长，再做功效分析确定正式样本量。若只能招募约 10--15 名合格人员，应将研究明确标为 exploratory，并避免强因果推广。
- 记录专业背景、从业年限、对报告类型的熟悉程度；控制系统呈现顺序和学习效应。

**主要指标：** 任务正确率、完成时间、来源追溯成功率、关键遗漏率、主观有用性和认知负担。安全相关遗漏应单独报告，不能被总平均分稀释。

**为什么要做：** 工程导航价值是一项用户层面的主张，只有真实任务表现能够直接支持。ROUGE 或阅读长度不能替代这一证据。

**决策门槛：** 若没有完成该实验，应删除“improves engineering decision-making/maintenance effectiveness”等表达；若只改善用时但不改善正确率，应将价值限定为导航效率，不能扩展为决策质量改善。

### 3.9 E8：未见报告系列与真实维护数据外部验证（P1/P2）

**目的：** 检验方法是否只适配当前 NERC 报告模板和术语。

**设计：**

- 最低方案：使用协议冻结后才获取或打开的未见 NERC 报告系列，确保整套系列不出现在开发数据中。
- 强化方案：增加其他机构的事故调查报告、维护记录或许可允许的工单文本；建立跨机构、跨文档类型的测试。
- 不同域分别报告结果，不要只汇总为单个平均数。若标签或参考摘要不可获得，至少执行 E6 的结构/忠实度标注和 E7 的任务评价。

**为什么要做：** 当前 15 份单一机构报告只能说明框架在特定技术报告上的行为，不能支持对维护场景的一般化结论。

**决策门槛：** 如果无法取得真实维护数据，应在标题、摘要、引言和结论中始终使用 technical-report proxy，并把真实维护应用列为未验证边界。

### 3.10 E9：系列级统计与稳健性分析（P1）

**目的：** 修正报告系列内相关性，并判断结果是否由个别系列驱动。

**设计：**

- 以报告系列为聚类单位执行 cluster bootstrap，报告配对差异的 95% 置信区间。
- 执行 leave-one-series-out 分析，展示每次移除一个系列后的效应方向和区间。
- 对预先指定的主要比较使用 Holm 等多重比较校正；探索性比较与确认性比较分开。
- 同时报告逐报告结果，但明确其从属于敏感性分析。

**为什么要做：** 当前聚类敏感性分析中，Full 对 Semantic-MMR 的 p 值约为 0.03125，对 TextRank 约为 0.04492，但在六项比较的 Holm 校正下不能继续按显著结果解释。这说明系列相关性会实质改变结论。

**通过标准：** 所有主要结论在系列级分析中方向稳定；若区间跨零，应使用“不确定”而不是“显著优于”的语言；不得用未校正的个别 p 值覆盖整体证据。

### 3.11 E10：系统化误差分析（P2）

**目的：** 将负向路径结果和失败案例转化为可复用的社区知识。

**设计：** 按布局类型、报告长度、角色类别、边方向、路径长度、跨段距离、共指需求和是否含表格分层。对 Full 优于、持平和劣于 strict 的案例分别抽样，追踪从候选切分、角色判断、图边、路径得分到最终选择的完整错误链。

**主要产出：** 错误分类表、每类频率、代表性匿名案例、可验证的机制假设，以及哪些错误可由实现修复、哪些属于方法边界。

**为什么要做：** 如果路径项继续为负，论文仍可通过严谨的失败机制分析贡献于社区；只报告平均数会使负向结果缺乏解释价值。

### 3.12 E11：端到端可复现性验证（P1）

**目的：** 验证“确定性、可追溯”是否在独立环境中成立。

**设计：**

- 在全新环境中按 README 从安装、数据构建、模型加载、实验运行到表格生成执行一次完整流程。
- 固定随机种子并重复运行主要实验；确定性步骤要求结果完全一致，含浮点或并行差异的步骤应预先定义容差。
- 校验源文件、处理中间文件、模型和最终结果的哈希；核对论文表格是否由已归档结果自动生成。
- 记录失败依赖、缺失资源、运行时间和硬件需求。

**为什么要做：** 当前测试出现 `rouge_score` 导入错误、部分测试未被发现、模型路径和数据入口不完整，与论文的核心可复现性定位直接冲突。

**通过标准：** 干净环境中完整测试全部通过；主要结果可重建；README 不依赖作者机器上的隐含路径；结果、日志和论文数值形成可追踪链条。

## 4. 推荐修订顺序

### 阶段 0：冻结边界与版本

先建立新版本和 protocol，标记哪些数据已经看过，哪些是真正未见留出集。此阶段不追求新结果，只防止后续证据污染。

### 阶段 1：修复实验基础

完成 E1 候选单元重建、E3 截断诊断和 E11 环境修复。若候选粒度和运行环境不稳定，不应进入大规模对比实验。

### 阶段 2：重跑核心定量实验

完成 E2 匹配预算、E4 平衡调参、E5 干净消融和 E9 系列级统计。这一阶段决定论文能否保留性能比较主张，以及路径项应保留、降级还是重设计。

### 阶段 3：补齐构念与应用证据

完成 E6 人工结构验证。若论文仍要强调应用价值，再完成 E7 专家任务研究和 E8 外部验证。没有 E6 时，不建议把结构感知作为已验证贡献；没有 E7/E8 时，不建议声称工程效用或真实维护泛化。

### 阶段 4：按最终证据重写正文

依次修改方法、结果、讨论、引言、摘要和标题。标题与摘要最后定稿，因为它们必须反映所有实验的最终结论。同步更新图表、补充材料、Data Availability、限制和 AI 使用声明。

### 阶段 5：投稿前审计

逐项执行以下一致性检查：每个 RQ 都有结果；每个贡献都有证据；每个表格都报告预算和不确定性；所有负向结果均可见；所有文件可由 README 定位；正文、补充材料和代码版本一致。

## 5. 最低可行修订与强修订方案

### 5.1 最低可行修订

若时间或数据受限，至少完成 E1、E2、E3、E4、E5、E9 和 E11，并在全文将论文定位为“可审计框架及路径组件的诊断性负向研究”。E6 若无法完成，必须大幅收缩结构正确性主张；E7/E8 未完成时，必须明确没有验证工程效用和真实维护泛化。该方案可以提高严谨性，但社区贡献主要来自透明框架、协议和负向机制分析，预计仍属于需要谨慎评估的应用研究。

### 5.2 强修订方案

在最低方案上加入 E6、E7 和 E8，形成“公平自动指标比较 + 结构有效性 + 专家任务效用 + 外部系列泛化”的证据链。如果匹配预算后仍有稳定优势、结构标注精度可靠、专家任务至少在正确率或时间上产生有意义的效应，论文才有充分依据恢复较强的应用贡献表述。

## 6. 结果驱动的主张决策门槛

| 新结果 | 正文应采取的处理 |
|---|---|
| Full 在匹配预算和平衡调参后仍稳定优于强基线 | 可主张受当前数据域支持的性能优势，但必须报告效应量、区间和域边界 |
| Full 的优势在匹配预算后消失 | 删除优越性主张，解释为内容分配策略差异，保留可审计框架贡献 |
| 归一化消融后路径项仍为负 | 从主性能模块移除或重设计；将其作为被证伪的设计假设报告 |
| 路径项只在特定文档类型有效 | 改为条件性组件，明确触发条件和不适用范围 |
| 人工角色/边/路径支持率低或一致性差 | 不再声称结构表示可靠；优先修正规则、标签体系或图构建 |
| 结构指标改善但 ROUGE 不改善 | 将贡献定位为结构忠实和可审计性，解释 ROUGE 的构念局限 |
| 专家任务只改善速度、不改善正确率 | 仅主张导航效率，不主张决策质量或安全性改善 |
| 无外部数据或专家研究 | 全文保留 proxy、exploratory 和 not yet validated 边界 |

## 8. 最终判断

本稿最需要解决的不是文字流畅度，而是评价构念、公平比较和路径组件证据三个层面的缺口。布局切分、匹配预算、平衡调参、系列级统计和可复现性属于修订期内可以完成的工程性问题；人工结构验证和专家效用研究需要额外组织，但仍可补救。路径项本身是否可救不能预设：干净消融后若继续稳定为负，应接受该设计假设未被支持，并调整方法与贡献定位，而不是继续通过表述弱化结果。对 *Applied Sciences* 而言，一篇诚实报告负向组件结论、但具有公平实验、直接应用评价和完整复现链条的论文，比保留未经验证的性能或工程价值主张更有说服力。
