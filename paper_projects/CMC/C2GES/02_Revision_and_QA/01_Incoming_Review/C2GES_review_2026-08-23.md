## Part 1. The Review Report

### Summary

本文提出 C²GES，一种面向长篇电力系统技术报告的确定性抽取式摘要框架，使用词汇角色、类型化句子图、节点删除路径参与度、冗余控制和页码溯源组织结构互补的证据；然而，当前最优结果来自去除路径删除项的 strict variant，Full C²GES 相对外部基线的比较又受到输出长度、候选切分、嵌入截断和调参机会不平衡的共同影响，因此现有证据主要支持“可审计、可溯源的框架及负向组件诊断”，尚不能支持路径删除组件有效或系统在公平条件下优于基线。

### Strengths

1. **负向结果报告和主张边界较为诚实。** 摘要、结果、讨论和结论均明确报告 strict variant 的 ROUGE-L 高于 Full，开发集校准也在 12/12 个留一报告折中选择零路径权重。稿件没有把“改变了 9774 个候选分数和 28/30 个选择序列”错误等同于“提高了摘要性能”。这种区分对社区有价值。

2. **实现具有较强的确定性和审计意识。** 稿件给出了角色规则、类型边、路径函数、权重、并列规则、工作量上限和页码定位方式。开发集和测试集按报告系列划分，本轮核查未发现同一 `report_series_id` 同时进入开发集和测试集。1575 个已选片段均保留了可解析的页码定位记录。

3. **实验结果报告相对完整。** 七个条件、两个预算和四个指标均被公开，报告级配对差异、输出长度、负向消融结果和后验开发校准没有被隐藏。统计部分也主动把 bootstrap sign-tail 量与校准的假设检验区分开，并说明 composition interval 不是总体置信区间。

### Weaknesses (Critical)

#### W1. 核心路径删除组件没有得到有效性支持，方法新颖性与实证结论之间存在结构性张力

Full C²GES 的 ROUGE-L 在 `K=5` 和 `K=10` 分别为 0.1060 和 0.1276，而 strict no-path-deletion variant 分别为 0.1094 和 0.1310。Full-minus-strict 的均值为 -0.003332 和 -0.003360，两个 composition interval 均跨零；后验开发校准又在 12/12 个留一报告折中选择零路径权重。由此可见，路径项虽然会改变排序，但没有增加预定义主终点。

更重要的是，strict variant 只是将路径项的 0.15 权重置零，没有归一化其他正向权重，也没有同步调整 0.50 的冗余惩罚。因此 Full 与 strict 的差异同时包含路径信息和评分尺度变化，不能被解释为路径信息的纯贡献。若类型化路径删除仍被作为论文的核心方法创新，当前证据不足；若将其改为被诊断失败的实验性组件，则论文仍可保留可审计框架和负向结果贡献。

**问题性质：** 方法贡献与实验证据不匹配，属于主要录用阻碍，但不是不可修复的算法错误。  
**需要的修复：** 重新定义主贡献，增加归一化消融和完整组件因子实验；若路径项继续稳定为负，应将其从默认 Full 方法中移出或重新设计。

#### W2. Full 相对 Semantic-MMR 和 TextRank 的比较目前不具备公平的性能解释

Full 的输出在相同单元数下比 Semantic-MMR 和 TextRank 长 54%--63%。部分候选单元超过 100 个词、包含表格标记，最大达到 270 词，因此“五个单元”并不等价于五个普通句子。更长的输出拥有更多机会与 Executive Summary 发生词汇匹配，直接影响 ROUGE。

比较还存在两项额外不平衡。第一，Full 使用 144 个开发配置，而 Semantic-MMR 的系数固定为 0.5，TextRank 使用默认设置。第二，Semantic-MMR 的代码直接调用 `SentenceTransformer.encode`，没有显式记录最大序列长度或超长单元处理；在存在长达 270 词的融合单元时，默认 tokenizer 截断可能使候选后半部分不进入嵌入，而 C²GES 的词汇通道仍使用完整文本。由此，当前差异混合了方法、输出长度、候选布局、截断和调参预算。

**问题性质：** 核心比较设计混杂。仅在文字中承认限制不能建立算法优势。  
**需要的修复：** 布局感知重切分、统一词数或 Token 预算、报告截断比例、平衡开发调参，并加入更强的现代抽取式基线。

#### W3. 评价指标没有直接检验论文声称的结构互补性和工程导航价值

ROUGE-L 衡量与官方 Executive Summary 的词汇重合，冗余度衡量选中单元间的词汇相似性。这两个指标都不能判断自动角色是否正确、类型边是否有真实语篇支持、路径是否覆盖了 condition–event–impact–mitigation 链、摘要是否遗漏关键风险、页码定位是否帮助工程人员完成任务。

当前角色与边完全由词汇规则、局部距离和 token overlap 决定，允许角色方向与文档顺序相反，也不处理否定、假设、引用和跨句共指。稿件已承认这些限制，但没有人工角色、边或路径标注来量化其严重程度。因此，“structure-aware”和“engineering reading aid”目前主要是设计意图，不是被直接验证的效果。

**问题性质：** 评价构念缺口。属于方法可保留但主张不能成立的主要问题。  
**需要的修复：** 增加人工结构有效性标注、来源忠实度和遗漏风险评价；若保留工程效用主张，还需要合格电力人员参与的任务实验。

#### W4. 样本规模、系列相关性和测试集历史限制了统计与外部有效性

测试集包含 15 份报告，但权利安全元数据表明它们只对应 10 个报告系列，其中 State of Reliability 系列含 4 份、Odessa 系列含 2 份、Winter Storm Elliott 系列含 2 份。正文的 paired bootstrap 和 exact sign-flip 以 15 份报告为独立单位，未在主分析中保留系列内共同符号或相关性。

本轮使用项目中的 `report_series_id` 做了一个审稿侧的系列块 sign-flip 敏感性检查：在六项比较内进行 Holm 校正后，`K=10` 下 Full 对 Semantic-MMR 和 TextRank 的差异不再低于 0.05。该检查不是作者的预注册结果，但足以说明系列相关性会实质改变统计解释，应由作者在正式脚本中复算并报告。

此外，报告来自单一机构，且正文承认测试报告在 corrective reconstruction 期间被检查过；冻结记录也将当前评价标为 `post_audit_corrective_descriptive_not_fresh_confirmatory`。因此，当前测试集不能再承担完全未见确认性证据的角色。

**问题性质：** 统计独立性和外部有效性问题。现有结果仍可作为描述性证据，但不能支持广泛泛化。  
**需要的修复：** 增加 cluster bootstrap、系列块置换、leave-one-series-out，并在协议冻结后使用未见报告系列或真实维护数据进行外部验证。

#### W5. 当前发布包与“可复现”主张尚未完全一致

本轮新鲜核查发现：

- `FILE_SHA256SUMS.txt` 共记录 113 个文件，其中最新 `paper_applsci.tex` 和 `supplementary_materials.pdf` 的哈希与清单不一致；
- 补充材料称机器可读文件位于 `transferable/`，但当前包没有该目录，实际文件位于 `05_Data/`；
- 补充材料和主文称 Table S1 是 40-report sampling frame，但补充 PDF 只给出汇总并指向不存在的 `transferable` 路径；
- 在当前干净 Python 3.8 环境执行完整测试发现 22 项、4 项错误，包括缺少 `rouge_score`、缺少 `run_test_v0_3`、硬编码外部 source manifest，以及 `SequenceMatcher.find_longest_match` 与 Python 版本不兼容；
- 依赖锁记录 Python 3.12 和包版本，但没有可直接创建环境的 `requirements.txt`、`environment.yml` 或锁定安装命令。

这些问题不证明论文数值错误，但会削弱“deterministic and reproducible”的核心定位。

**问题性质：** 发布工程缺陷，可在修订期内完全解决。  
**需要的修复：** 统一目录与清单、提供环境创建文件、区分公开可运行测试与受限数据测试，并在全新环境执行端到端验收。

### Fatality Assessment

当前未发现单个已经被证实、且无法通过重新实验或降低主张修复的致命问题。W1--W4 是接收前必须解决的结构性证据缺口，W5 是必须修复的工程问题。若作者不补充实验，则论文只能被重新定位为“确定性审计框架和负向组件诊断”，不能继续暗示公平性能优势或工程效用已经成立。

### Rating

**5/10（Major Revision）**。稿件在透明度、确定性实现、来源追踪和负向结果报告方面具有真实价值，但核心路径组件未带来收益，系统级比较受到多重混杂，结构与工程价值缺少直接评价，统计独立性和复现包也需补强。完成匹配预算、平衡调参、干净消融、系列级分析和人工/外部验证后，论文有机会达到 *Applied Sciences* 的可接受水平。

## 3. 文本部分修改任务

### T1. 标题、摘要与关键词

**修改内容：** 标题可以保留 “Structure-Aware” 和 “Typed-Path Graphs”，但正文必须把它们解释为方法属性，而不是性能结论。摘要继续先报告 strict variant 最优，再报告 Full 的绝对值、长度混杂和路径项负向结论。若新增实验尚未完成，不得使用 “outperforms”“improves engineering review”“effective structural reasoning”等无条件措辞。

**原因：** 当前最可靠的贡献是框架透明性和负向组件诊断，不是路径项有效或公平优越性。

**完成标准：** 摘要中每个效果性动词都能在匹配预算结果或人工评价表中找到直接证据。

### T2. 引言、研究问题与贡献定位

**修改内容：** 将研究问题改为与新实验一一对应：

1. 在相同词数或 Token 预算、平衡调参条件下，各系统如何比较；
2. 角色预留、类型边、图显著性和路径项分别贡献什么；
3. 自动角色、边和路径得到多少人工支持；
4. 仅在完成专家实验时，研究结构化输出是否改善工程人员的正确率、用时或遗漏风险。

贡献段应分为“确定性来源链接框架”“公平评价与结构验证协议”“对路径项的实证结论”。如果路径项继续为负，负向结论本身可以保留为贡献，但不应继续把 Full 版本作为默认最佳系统。

**原因：** 现有 RQ1--RQ3 能解释旧实验，却没有直接检验标题中的结构与应用价值。新 RQ 应迫使每个贡献拥有对应结果。

### T3. 相关工作与基线定位

**修改内容：** 相关工作按位置/中心性、无监督语义排序、图摘要、长文档抽取、技术报告与电力文本分析分组。增加基线定位表，列出候选粒度、编码长度、训练需求、调参配置数、长度约束和来源链接能力。

在新实验中至少加入一个更现代的无监督语义抽取基线、一个长文档或学习式抽取基线，以及一个预算约束明确的 LLM/重排序基线（若许可和资源允许）。所有具体引用在加入论文前应核验其真实存在和任务可比性。

**原因：** 仅与 Lead、Centroid、TextRank 和固定系数 Semantic-MMR 比较，难以代表当前长文档摘要水平；同时不能给 C²GES 更多调参机会。

### T4. 数据来源、抽样与划分

**修改内容：** 明确 40 份报告如何从 NERC 文档总体中选出，包括检索日期、集合入口、纳入范围和预先排除规则。主文或补充材料报告 27 份保留文档的系列、年份、类型、页数和候选数量。明确 15 份测试报告对应 10 个系列，并说明开发/测试之间没有系列交叉。

对现有 test 使用 “retained descriptive test set” 或等价表述，不再把它当作完全未见确认性数据；新实验使用协议冻结后才打开的外部系列。

**原因：** 报告系列是更合理的独立性和泛化单位，测试集历史也决定了证据等级。

### T5. 候选单元与布局处理

**修改内容：** 将当前 candidate 明确称为 extraction unit，而不是一律称为 sentence。详细说明页眉页脚、标题、项目符号、表格、跨行文本和跨页断句的处理规则。报告单元词数、字符数、WordPiece 长度、表格型单元比例、超过编码上限比例和过滤比例。

**原因：** 当前存在 100--270 词的融合单元，候选粒度是输出长度和 ROUGE 混杂的直接来源。

### T6. 嵌入模型与截断

**修改内容：** 正文记录 `all-MiniLM-L6-v2` 的 revision、tokenizer、`max_seq_length`、padding、truncation 和超长单元处理。新实验比较默认截断、布局切分、滑窗/分块池化或适合长单元的编码方式。

**原因：** Semantic-MMR 只看被编码的文本部分，而词汇方法使用完整单元。截断不透明会产生隐藏的基线劣势。

### T7. 评分函数、消融和术语

**修改内容：** 将现有 strict variant 始终称为 “unrenormalized coefficient-removal comparison”。新增 normalized no-path 版本，并说明删除路径项后如何保持正向权重总和及冗余惩罚的相对尺度。避免继续使用具有物理因果含义的 counterfactual 术语；代码、图、表和正文统一使用 path-deletion 或 typed-path participation。

**原因：** 当前 strict 差异不等于路径信息的纯效应；术语也必须与“文本代理图”边界一致。

### T8. 统计分析

**修改内容：** 新主分析以报告系列为 cluster，报告 cluster bootstrap、系列块随机化/置换和 leave-one-series-out。报告每个系统的均值、配对差异、区间、效应量、实际输出长度和多重校正结果。逐报告分析保留为敏感性分析。

预先定义主要终点和最小实际差异；不要把 post-result sign-flip 当作预注册确认结果。若系列级结果与逐报告结果不同，以系列级结论作为主要解释。

**原因：** 同一系列共享模板、术语和事件背景。把 15 份报告全部视为独立会低估不确定性。

### T9. 结果、讨论和结论

**修改内容：** 结果按以下顺序重组：候选与布局诊断；匹配预算主比较；平衡调参比较；干净消融；人工结构有效性；系列级稳健性；专家/外部验证。原有 equal-unit 结果降为辅助分析。

讨论中分别回答：框架是否可运行、路径项是否有效、结构代理是否被人工支持、系统是否在公平预算下更好、结论能否迁移到维护记录。若某一层证据不存在，就明确标为未回答。

**原因：** 当前叙述已经较诚实，但仍需要让公平比较和直接构念验证成为主结果，而不是只出现在 Future Validation。

- 核对 GitHub 发布内容与投稿包是否为同一版本，并为公开 release 提供提交哈希或 tag。

**原因：** 可复现性是本文主要卖点之一，发布包中的路径和清单不能依赖作者工作站的隐含状态。

## 4. 必须补充的实验

### E0. 冻结新的确认性协议

**优先级：P0。**

在打开新外部测试系列前冻结：候选切分规则、模型版本、各系统搜索空间、输出预算、随机种子、主要终点、cluster 定义、统计方法、排除规则和多重比较族。保留带日期的 JSON/YAML 协议和代码提交哈希。

**为什么要做：** 当前测试已被用于 corrective reconstruction，新实验必须重新建立未见评价边界。

**完成标准：** 新测试数据的哈希在协议文件中出现，但在方法和参数冻结前不可用于调参或误差分析。

### E1. 布局感知候选重建与质量审计

**优先级：P1。**

**设计：** 重新处理 PDF，区分正文句、标题、列表项、表格行、页眉页脚和脚注；修复跨行与跨页断句。对旧版与新版候选分别报告单元总数、长度分布、表格污染率、超长率和抽样人工有效率。

**指标：** 有效句/单元比例、融合错误率、截断率、每报告候选数、选中输出词数、ROUGE 和人工来源忠实度。

**原因：** 候选布局污染是长度差异、嵌入截断和 ROUGE 优势的共同上游原因。

**完成标准：** 分层抽样人工审计达到预先设定的单元有效率；主实验不再由长表格融合块驱动。

### E2. 匹配词数或 Token 预算的主要比较

**优先级：P1。**

**设计：** 除保留 `K=5/10` 外，预先定义至少两个词数或 Token 预算，例如短预算和中预算。每个系统在选择时受到同一预算约束，而不是输出后截断。明确不能完整放入剩余预算的单元如何处理。

**比较：** Full、推荐的最终 C²GES 版本、normalized no-path、Semantic-MMR、TextRank、Role、Lead，以及新增强基线。

**指标：** ROUGE-1/2/L、BERTScore 或其他经验证的语义指标（若加入须说明适用边界）、实际词数、冗余、覆盖率和人工忠实度。

**原因：** 这是判断系统级优势是否真实存在的最低要求。

**完成标准：** 每个系统的平均实际长度处于预定义容差内；主结论来自匹配预算结果，equal-unit 结果仅作补充。

### E3. 嵌入截断敏感性实验

**优先级：P1。**

**设计：** 统计所有候选的 tokenizer 长度和被截断比例；比较默认截断、布局感知短单元、分块池化和长上下文编码方案。保证 Semantic-MMR 与其他使用嵌入的基线使用同一编码策略。

**原因：** 长候选可能使 Semantic-MMR 只表示前半部分，造成隐性不公平。

**完成标准：** 论文报告截断数量和结果敏感性；若不同编码方式改变系统排序，必须在讨论中解释。

### E4. 平衡调参与强基线比较

**优先级：P1。**

**设计：** 所有可调系统使用相同开发系列和预先设定的搜索预算。公开每个系统的搜索空间、配置数、选择目标和并列规则。至少加入一个现代无监督语义抽取方法和一个长文档/学习式抽取方法；若加入 LLM 排序，应控制调用预算并保留确定性设置或重复性分析。

**原因：** Full 的 144 配置与固定系数/默认基线不可直接比较。

**完成标准：** 不再出现“一个系统开发搜索、其他系统默认参数”的主要比较；所有基线均有版本和选择记录。

### E5. 干净的组件因子消融

**优先级：P1。**

**最少条件：**

1. relevance only；
2. relevance + role score；
3. 加入 role-group reservation；
4. 加入 untyped graph salience；
5. 加入 typed edges；
6. 加入 normalized path-deletion；
7. 加入/移除 redundancy penalty；
8. 当前 Full 与当前 unrenormalized strict，作为历史对照。

采用因子设计或预先指定的逐步比较，尽量只改变一个机制。删除正向项时保持评分尺度和冗余惩罚相对比例一致。

**指标：** 匹配预算性能、结构人工精度、选择集合 Jaccard、路径覆盖、冗余和跨系列稳定性。

**原因：** 当前 Role baseline 与 Full 同时在选择器、图和冗余上不同，无法判断收益究竟来自角色预留、图显著性还是其他规则。

**完成标准：** 论文能对每个核心模块给出直接贡献判断；无收益模块不再被包装为已验证创新。

### E6. 角色、边和路径的人工结构有效性

**优先级：P1。**

**设计：** 从不同报告系列、不同布局和不同自动置信度中分层抽样。至少两名独立标注者判断：

- extraction unit 是否有效且来源忠实；
- root cause、trigger、propagation/response、impact、mitigation 或 abstain；
- 自动类型边是否有文本证据，方向是否合理；
- 路径是否构成可解释的工程事件链；
- 摘要是否遗漏关键影响或缓解信息。

标注者应具备电力系统可靠性报告或相关技术文档经验，并允许 “无法判断”。报告一致率、仲裁前分歧、仲裁后标签、precision/recall/F1 和按角色/关系类型的误差。

**原因：** 这是验证 “structure-aware” 的直接证据，ROUGE 无法替代。

**完成标准：** 预先定义最低可接受精度或置信区间；若某类角色或边表现差，应调整规则或降低相关主张。

### E7. 专家任务效用研究

**优先级：P2；若保留 engineering reading aid 主张则升级为 P1。**

**设计：** 让合格电力人员在原报告、Lead/语义基线摘要和 C²GES 摘要之间进行随机、盲化或交叉任务。任务包括定位根因、触发、影响、缓解措施和源页。记录答案正确率、完成时间、遗漏关键风险、回到原页次数和主观负荷。

**原因：** 页码可解析不等于页码导航能提高工作效率或降低风险。

**完成标准：** 预先定义主要任务终点并报告配对效应；若无效，删除工程效用表述，保留可追溯性作为系统属性。

### E8. 未见系列与真实维护数据外部验证

**优先级：P1/P2。**

**最低方案：** 协议冻结后新增完整未见 NERC 报告系列，整套系列不得进入开发集。  
**理想方案：** 使用许可允许的维护记录、工单或检查报告，并重新定义合适的参考和专家任务。

**原因：** 当前 NERC 报告是 maintenance-oriented proxy，不代表真实资产级维护文本。

**完成标准：** 外部数据在开发期间不可见；单独报告外部结果，不与旧 test 混合；解释数据分布差异和性能下降。

### E9. 系列级统计与稳健性

**优先级：P1。**

**设计：**

- 以 `report_series_id` 为 cluster 执行 cluster bootstrap；
- 做系列块 sign-flip 或置换检验；
- 做 leave-one-series-out，展示删除每个系列后的效应；
- 报告每个系列的报告数和权重；
- 预先决定 estimand 是报告等权还是系列等权，并提供另一种作为敏感性分析。

**原因：** 15 份测试报告只对应 10 个系列，系列内相关性会改变区间和多重校正后的结论。

**完成标准：** 主要结论在系列级分析中方向稳定；若区间跨零或校正后不显著，使用“不确定”而不是“显著优于”。

### E10. 系统化误差分析

**优先级：P2。**

按布局错误、角色误分、否定/假设、共指缺失、反向边、超出 12 单元距离、长单元截断、参考摘要不覆盖和关键工程信息遗漏分类。对 Full 优于/劣于 strict 和基线的报告分别抽样，避免只展示成功案例。

**原因：** 路径项为负可能来自多个不同机制；没有错误分析，无法判断该组件应调整权重还是重建语义。

### E11. 端到端复现验收

**优先级：P0。**

**设计：** 在全新 Python 3.12 环境中，按 README 的单一命令完成环境创建、公开测试、受限数据检查、结果表重建、图生成和 LaTeX 编译。自动验证论文表格数值、补充材料路径和全部哈希。

**需要修复的已知点：**

- 显式安装 `rouge-score` 等根依赖；
- 处理或移除缺少 `run_test_v0_3` 的过期测试；
- 让 Python 版本要求与 `SequenceMatcher` 调用一致；
- 将外部 source manifest 改为配置路径，并对缺失受限数据给出明确 skip；
- 更新两个不匹配的哈希；
- 修正 `transferable/` 路径；
- 输出实际测试通过/失败/跳过数量，而不是沿用旧环境记录。

**完成标准：** 干净环境下公开子集零错误；受限数据测试被明确标记而非误报失败；主要结果和最新 LaTeX 的哈希可由同一发布流程生成。

### 强修订方案

## 7. 结果驱动的决策规则

- 若 normalized path-deletion 在匹配预算和新留出集上仍无收益，应将其降级为实验模块，默认系统采用表现更稳定的无路径版本；
- 若自动角色/边精度不足，应重设计规则或把图明确称为 heuristic textual proxy，不再暗示工程事件结构；
- 若匹配预算后 Full 不再优于基线，应删除系统优越性叙述，突出可追溯、确定性和负向诊断；
- 若专家任务没有改善正确率、时间或遗漏风险，应删除 reading aid 的效果性措辞，只保留 source-linked navigation 能力；
- 若外部系列结果明显下降，应报告分布转移，不用旧 NERC test 的结果代替泛化证据；
- 若复现包不能在干净环境运行，不应在摘要或结论中使用 reproducible 作为未经限定的核心卖点。

## 9. 最终判断

C²GES 当前不是一篇存在明显数值造假或不可挽救方法错误的论文。相反，它的最大优点是对负向组件结果、长度差异和调参不平衡进行了较充分披露。但披露限制只能防止过度宣称，不能把受混杂的比较转化为有效证据。下一轮工作的重点应从继续润色转向公平比较、结构构念验证、系列级统计和干净复现。只要作者接受路径项可能继续为负，并根据新证据调整默认方法和贡献定位，该研究仍具有成为一篇可信应用型论文的潜力。
