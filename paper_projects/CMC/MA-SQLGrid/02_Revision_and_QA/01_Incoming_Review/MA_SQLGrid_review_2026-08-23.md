- **P2：增强项。** 用于提高完整性、可读性和应用价值，不单独决定论文有效性。

所有新增实验都以“协议执行完整、结果如实报告”为完成标准，**不以得到正向或显著结果为完成标准**。测试集、阈值、主要终点和比较族必须在看结果前冻结，不允许根据结果反向改设计。

## 3. 文本部分需要修改的内容

### 3.1 标题与论文定位

**需要修改：** 如果不能完成完整的前瞻性端到端实验，建议把标题从强调多智能体有效性的表达调整为：

> MA-SQLGrid: An Auditable Coordination and Evaluation Framework for Power-Grid Text-to-SQL

正文应把贡献定位为“可审计协调、安全执行和候选选择诊断框架”，而不是已经得到充分验证的多智能体性能提升方案。

**原因：** 当前历史池实验没有调用 SQL Synthesizer 生成 SQL，Schema Cartographer 的输出也没有真正参与候选决策。因此，现有数据支持的是协调与选择机制，而不是完整五角色流程的因果优势。标题和核心贡献必须与实验实际覆盖范围一致。

**完成判据：** 标题、摘要、引言贡献、讨论和结论对系统能力的描述保持一致；任何“multi-agent improvement”“end-to-end advantage”类表述都必须有新增端到端实验支撑。

### 3.2 摘要

**需要修改：** 不再孤立陈述“从 80 提升到 100/101”。应说明 80 是冻结的 C000/Qwen-F00 固定顺序控制，并同时报告八个固定来源中的最佳结果。推荐采用以下信息顺序：

1. 框架解决的审计和安全执行问题；
2. GridDB、BIRD、构造状态和历史候选池各自回答什么问题；
3. selector 相对 C000 的结果；
4. 最佳固定来源、并列数量和顺序敏感性；
5. 明确当前实验不能证明完整五角色架构的端到端优势。

**原因：** 同一候选来源中的 Qwen-F01 已达到 129/180，而 full-evidence selector 为 101/180。若只报告 80→101，会造成 selector 优于合理固定策略的错误印象。

**完成判据：** 摘要中的每个数值均能在主文表格中找到对应行；摘要同时呈现收益和限制，不选择性省略最佳固定来源。

### 3.3 引言、研究问题与贡献列表

**需要修改：** 将研究问题和贡献拆分为三个证据层级：

- 生成层：不同 prompt/context/value 组织方式是否影响 SQL 生成；
- 选择层：在冻结候选池中，验证和证据门控如何影响选择；
- 系统层：完整角色协作在预算匹配条件下是否优于简化流程。

若没有新增端到端实验，应删除或降级系统层研究问题，明确本文尚未回答这一问题。贡献列表中应把“框架设计”“安全与审计机制”“选择器诊断结果”分开书写。

**原因：** 当前稿件容易把不同实验层级并置，读者可能误认为历史选择实验等同于完整 MA-SQLGrid 实验。

**完成判据：** 每条研究问题均在结果部分有专门的小节和直接回答；每项贡献都能映射到至少一个实验或可检查的软件制品。

### 3.4 方法与系统架构

**需要修改：** 增加一张“角色输出—下游使用者—是否进入最终决策”的表格，至少覆盖 Query Analyst、Schema Cartographer、SQL Synthesizer、Validator、Counterfactual Critic 和 Adjudicator/Controller。对每个实验明确哪些角色被启用、替换或旁路。

历史池实验需要明确写出：SQL 候选来自 Frozen Candidate Provider；SQL Synthesizer 没有在线生成；Schema Cartographer 的输出是否参与评分；Validator 使用了哪些特征；Counterfactual witnesses 如何影响 eligibility；最终 tie-breaking 如何依赖候选顺序。

**原因：** 仅展示角色流程图不足以证明所有角色在实验中发挥作用。必须区分“生成轨迹”与“真正影响决策”。

**完成判据：** 任何角色均不存在只在图中出现、但方法和实验中无法判断其作用的情况；论文与代码 README 对角色数量和 Controller/Adjudicator 的定义一致。

### 3.5 评价协议与统计方法

**需要修改：** 新增 evaluator 版本、预测制品版本、空结果处理、SQL 执行比较、超时、错误值和 canonicalization 的精确定义。说明 76/180 与 80/180 分别使用了哪一份候选、哪一个数据库快照和哪一版 evaluator；若应当可比则统一重算，若本来不可比则在表题和正文中明确区分。

将“registered analysis”改为“documented and frozen before the reported reanalysis”，除非作者能够提供分析前注册的时间戳材料。明确区分探索性分析、审稿后冻结的再分析和真正的前瞻性确认实验。

统计部分应预先定义主要终点、比较族和校正方式。新实验优先使用题目级配对差异，报告准确率差、区间估计和 Holm 校正结果；不得只比较未校正的单个 p 值。

**原因：** 候选版本或评价器漂移都会破坏不同表格之间的可比性；“registered”若实际是事后冻结，也会被视为不准确的方法学表述。

### 3.6 结果部分

**需要修改：** 将结果按“生成实验—选择器实验—系统实验”分层，不将它们合并为同一种证据。在历史选择器表格中加入全部八个固定槽、开发集冻结的最佳固定来源、C000、validation selector、full-evidence selector 和 oracle 上界。

结果部分还应单列：

- 四个空结果争议样本的处理结果；
- 原始槽位级和规范化唯一 SQL 级的并列率；
- 多次随机排列候选顺序后的准确率分布；
- 每个角色消融后的准确率、拒答率、成本和延迟；
- 新增未见电力测试集上的结果和专家语义正确率。

**原因：** 当前最重要的不是增加更多零散表格，而是让每个表格对应一个清晰的因果或诊断问题。

### 3.7 讨论、局限性与结论

**需要修改：** 讨论中必须明确区分：

- 选择器相对 C000 有改进；
- 选择器未超过候选池中的最佳固定来源；
- 顺序反转可使结果由 101 变化到 117–118；
- 历史池结果不能证明对新问题的泛化；
- BIRD 证明的是一般数据库迁移，不是电力领域有效性。

结论不得使用“robust”泛指总体稳健性，应限定为 mutation denial、bounded execution 和 incomplete-evidence fail-closed 等已实际检验的维度。

**原因：** 论文真正有价值的发现之一正是高并列率和顺序敏感性。将这些发现当作限制隐藏，会削弱可信度；将其上升为公开的诊断结论，反而能够形成贡献。

### E1. 统一评价器下的八槽固定来源基线

**优先级：P0；是否需要重新调用模型：否。**

**设计：** 使用同一个 evaluator 和同一份 180 题数据，分别固定选择 Qwen-F00、F01、F10、F11 和 Granite-F00、F01、F10、F11，再评价 C000、validation selector 和 full-evidence selector。另以开发集选择一个固定来源，在评价集上冻结测试。Oracle-best-of-eight 只能作为候选池上界。

**报告：** 每个方法的正确数、准确率、相对 C000 和开发集冻结基线的题目级配对差异、区间估计及校正后显著性。

**原因：** 该实验用于消除弱基线选择偏差，判断 selector 的收益究竟来自证据机制，还是仅来自避开较差的首槽。

**完成判据：** 所有方法由同一脚本、同一 evaluator 一次性生成；论文不再只使用 C000 代表固定策略。

### E2. 空结果评价一致性审计

**优先级：P0；是否需要重新调用模型：否。**

**设计：** 先确认生成表中的 Qwen-F00 与历史池首槽是否来自完全相同的预测制品；再逐条审查 Q104、Q107、Q110 和 Q140，记录 gold SQL、候选 SQL、数据库快照、实际结果集、预期结果集和 evaluator 判定。若两组制品相同，制定唯一的空结果规则并重新生成所有相关表格；若不同，则为二者分配不同 artifact ID，并解释差异来源。

**原因：** Qwen-F00 的 76/180 与固定首槽 80/180 的表面差异集中于这四题。若候选或评价定义不一致却没有显式标注，后续统计比较就没有清楚的共同基础。

**完成判据：** 同一 artifact、同一数据库快照和同一 evaluator 下的候选在所有实验表中得到完全相同的判定；不同 artifact 不再共享容易混淆的名称。正文附上规则，补充材料提供逐题审计记录。

### E3. 并列、重复候选与顺序敏感性实验

**优先级：P1；是否需要重新调用模型：否。**

**设计：** 先对 SQL 做规范化并识别语义等价候选，同时保留原始槽位级分析。至少进行 1,000 次候选顺序随机排列，报告准确率分布、选择来源比例、并列规模和最差/中位/最好表现。补充确定性 tie-breaker，例如规范化 SQL 去重、稳定来源优先级或基于开发集冻结的二级评分。另在未见数据上预注册三种决策策略：最高分并列时直接拒答、按冻结的 margin 阈值拒答、向用户请求一次澄清；报告 accuracy--coverage/risk--coverage 曲线、AURC、拒答率和澄清后的净收益。

**原因：** 130/180 个样本存在并列，且原序与逆序差异明显。两种固定顺序不足以刻画系统稳定性。

**完成判据：** 给出顺序扰动分布而非两个点估计，并说明最终 tie-breaker 在部署时是否与候选呈现顺序无关；拒答和澄清策略的阈值必须在测试集揭盲前冻结。

### E4. 角色利用率审计与逐角色消融

**优先级：P1；是否需要重新调用模型：部分需要。**

**设计：** 对每个角色记录其输出是否改变下游状态、候选得分、eligibility 或最终答案。随后进行完整流程与以下消融的比较：去除 Schema Cartographer、去除 Validator、去除 Counterfactual Critic、去除证据门控、去除多候选生成。

**指标：** execution accuracy、专家语义正确率、拒答率、unsafe acceptance rate、角色改变最终决策的题目比例、token、调用次数和延迟。

**原因：** 角色存在于轨迹中不等于角色对结果有贡献。该实验用于判断哪些模块是有效设计，哪些只是记录性组件。

**完成判据：** 每个被论文列为核心贡献的角色都必须有明确的信息流和至少一个可解释的消融结果；若某角色没有作用，应从核心贡献中移除或改为可选审计模块。

### E5. 预算匹配的前瞻性端到端实验

**优先级：P1，属于决定核心主张能否成立的实验；需要重新调用模型。**

**对照条件：**

1. Direct single-call generation；
2. Schema-grounded single-candidate pipeline；
3. Multi-candidate generation + Validator；
4. Full MA-SQLGrid；
5. Full MA-SQLGrid without counterfactual witnesses。

所有条件必须使用同一模型快照、相同解码参数、相同最大物理调用次数、近似相同 token 预算和相同重试规则。测试集在 prompt、阈值和 tie-breaker 冻结后才能揭盲。

**指标：** execution accuracy、semantic accuracy、拒答率、risk–coverage curve、调用失败率、平均/分位延迟、输入输出 token 和单位正确答案成本。

**原因：** 只有这一实验能够直接回答完整多角色框架是否优于简化流程。若不同方法的调用次数和 token 不匹配，任何性能提升都可能仅来自额外计算预算。

**完成判据：** 在未见测试集上完成预先定义的主要比较，并同时报告效果和计算成本；若无显著或实际收益，应将结论改为审计性和安全性贡献，而不是性能优势。

### E6. 未见电力数据库测试集与专家语义审核

**优先级：P1；需要新增数据和人工审核。**

**设计：** 构建 GridDB-v2 或选择许可允许的外部电力数据库。测试 schema 和问题在系统开发期间保持不可见，并按 schema 或问题族隔离训练/开发/测试。问题至少覆盖设备状态、时间窗口、单位换算、聚合粒度、设备—母线关系、拓扑关系和缺失值语义。

由至少两名电力领域专家独立审核自然语言问题和 gold SQL，再由一名数据库专家或第三位专家仲裁分歧。报告一致率、仲裁数量和最终错误类型。

**原因：** 当前 GridDB 较小且模板化，BIRD 又不属于电力领域。没有未见数据和专家审核，无法证明方法解决了真实电力语义问题。

**完成判据：** 提供独立测试集的数据卡、生成/采集流程、专家审核协议和错误类型统计；主文将其作为电力领域有效性的主要证据。

### E7. 风险—覆盖率与失败模式分析

**优先级：P1（若保留 fail-closed、clarification 或可靠性主张）；否则为 P2。**

**设计：** 在开发集上确定 evidence eligibility、margin 和拒答阈值，测试集只评价一次；绘制 coverage 对 error/unsafe acceptance 的关系，并报告 AURC。对错误进行分类：错误表或连接、过滤条件、聚合、投影列、时间边界、单位、状态语义、拓扑语义、空结果、执行失败和证据不完整。由领域专家审核高风险接受和错误拒答案例。

**原因：** MA-SQLGrid 的优势更可能体现在安全拒答和可审计性，而不是绝对准确率。风险—覆盖率比单一 accuracy 更能检验 fail-closed 设计是否有应用价值。

### E8. 可复现性验收实验

**优先级：P0。**

**设计：** 在全新环境中执行单一入口，完成依赖安装、数据检查、全部测试、核心表格重建和 LaTeX 编译。所有路径改为项目相对路径或配置项；重新生成最新文件哈希；补齐缺失的 comparison、state manifest、派生 JSON 或明确其受限原因。

**原因：** 当前校验首先因最新 LaTeX 与旧哈希不一致而失败，多个测试还依赖旧绝对路径或缺失文件。旧工作区中的测试通过记录不能替代当前提交包的实际可复现性。

**完成判据：** 在干净环境中从零执行成功；新的 QA 报告记录命令、环境、通过/失败/跳过数量以及无法公开的数据边界。过期 PDF 不得作为最新稿件校验依据。

### E9. 扩展 metamorphic 与多状态证据实验

**优先级：P1（若将 counterfactual/state evidence 列为核心贡献）；否则为 P2。**

**设计：** 扩展当前 mostly structural 的 metamorphic witnesses，加入经专家确认保持业务语义的变换，例如同义状态映射、时间窗口边界、单位等价转换、无关行插入、等价连接路径和拓扑保持变换。每个变换先由领域专家确认其前提和预期不变量，再冻结测试清单。分别报告 witness 的可执行率、检错增益、误拒绝率，以及相对 execution-only selector 的题目级变化。

**原因：** 当前有限 witnesses 只额外带来约 1 个匹配，而且 SQL 执行等价或简单不变量并不能证明答案符合预期业务语义。扩展并人工验证变换，才能检验 counterfactual/state evidence 是否真的提供独立信息。

**完成判据：** 每个变换都有前提、预期不变量、专家确认和自动化测试；完整报告正向、零增益和负向结果，不只保留有效案例。

### E10. 跨数据库可迁移性与规模/成本实验

**优先级：P2。**

**设计：** 在许可允许的第二个电力数据库或从 RTS-GMLC、SimBench 等资源合法派生的关系型任务上复现实验，并由专家审核 gold SQL。同步扩大 schema 数量、表行数和查询复杂度，测量物理模型调用次数、输入/输出 token、端到端延迟、峰值内存、超时和失败率。所有方法使用相同执行器和预算口径。

**原因：** BIRD 能支持一般数据库迁移讨论，但不能单独支持电力领域迁移；小型 GridDB 也无法说明在更大 schema 和数据量下的部署可行性。成本与延迟还是公平解释多角色方法收益的必要条件。

**完成判据：** 数据来源和许可清楚；跨库指标与主实验口径一致；性能、成本和失败案例全部报告。若无法获得第二个合法电力数据源，应把结论限定为单一电力基准上的证据。

## 5. 新实验的统计与报告约束

新增实验开始前应冻结以下内容，并保存带时间戳的配置：主要终点、测试集、模型版本、prompt、调用预算、随机种子、空结果规则、canonicalization、tie-breaker、排除规则和多重比较族。

统计报告遵循以下原则：

- 主要比较使用题目级配对分析，不使用两个独立比例检验代替配对检验；
- 同一研究问题中的多个比较统一进行 Holm 校正；
- 同时报告绝对正确数、准确率差、区间估计和原始/校正后 p 值；
- 将统计显著性与实际意义分开，预先定义最小实际改进幅度；
- 模板族、SQL 等价组或 schema 可能导致相关性时，增加相应的分组重采样敏感性分析；
- Oracle 结果、开发集选模结果和测试集确认结果必须分别标记，不得混合解释。
