## 4. P1：保留强主张时必须完成

### M-P1-01 并列、去重和顺序敏感性

设计：同时保留原槽位分析和规范化唯一 SQL 分析；至少 1,000 次候选顺序随机排列，报告准确率分布、来源比例、top-tie 大小及最差/中位/最好值。tie-breaker 只能用开发数据冻结，不能因反转顺序得到 117--118 就事后采用。

扩展：在未见集预注册 top tie 直接拒答、margin 拒答和一次澄清策略；报告 accuracy/risk--coverage、AURC、拒答率和澄清净收益。  
验收：最终规则与候选呈现顺序无关，或明确说明仍有顺序依赖并降低主张。

### M-P1-02 角色利用率与逐角色消融

为 Query Analyst、Schema Cartographer、SQL Synthesizer、Validation Engine、Metamorphic-State Critic 记录：输出是否进入下游、是否改变候选/score/eligibility/final answer。比较完整流程与移除 Cartographer、Validator、Critic、证据门控和多候选生成。

指标：execution accuracy、专家语义正确率、拒答、unsafe acceptance、角色改变最终决策比例、token、调用次数和延迟。  
验收：每个核心角色有真实信息流与消融结果；无作用角色降级为可选审计模块。

### M-P1-03 预算匹配的前瞻性端到端实验

条件：Direct single-call；schema-grounded single candidate；multi-candidate + Validator；Full MA-SQLGrid；Full without state witnesses。

控制：相同模型快照、解码、最大物理调用数、近似 token 预算、重试规则、执行器和 evaluator；测试集在 prompt/阈值/tie rule 冻结后揭盲。  
报告：execution/semantic accuracy、拒答、risk--coverage、失败率、延迟、token 和单位正确答案成本。  
验收：只有该实验支持完整五角色系统效果；若无实际收益，论文回到可审计框架定位。

### M-P1-04 未见电力测试集与专家审核

设计：构建许可允许的 GridDB-v2 或外部电力库；按 schema/问题族隔离开发和测试；覆盖状态、时间窗、单位、聚合、设备—母线、拓扑和缺失值。至少两名电力专家独立审问题/gold SQL，数据库专家或第三人仲裁。

验收：有数据卡、权利依据、冻结流程、一致率和错误类型；主文将其作为电力领域有效性证据。无法取得合法数据时必须限定为单一合成基准。

### M-P1-05 风险—覆盖率与失败模式

在开发集冻结 eligibility、margin 和拒答阈值；测试集仅评价一次。分类错误表/连接、过滤、聚合、投影、时间边界、单位、状态、拓扑、空结果、执行失败和证据缺失；专家审核高风险接受及错误拒答。

验收：如果保留 fail-closed/clarification/可靠性主张，主结果必须含 risk--coverage/AURC，而非只给 accuracy。

### M-P1-06 扩展 metamorphic/state 证据

若 state evidence 继续作为核心贡献，加入经专家确认保持业务语义的同义状态、时间边界、单位等价、无关行、等价连接和拓扑保持变换；报告可执行率、检错增益、误拒率及相对 execution-only selector 的题目级变化。

验收：每个变换有前提、不变量、专家确认和自动测试；零增益/负向结果完整保留。

## 6. 论文路线选择

### 路线 A：范围收缩的最低可投稿版本

完成全部 P0，把题目和贡献定位为“可审计协调、安全执行和候选选择诊断框架”。保留 80/100/101 只作为冻结历史池内的描述性结果；删除完整多角色端到端优势、电力泛化和总体稳健性主张。无需新增模型调用，但仍可能因电力证据弱而被要求大修。

### 路线 B：推荐的科学增强版本

在 P0 上完成 M-P1-01、03、04、05；若角色贡献和 state evidence 是核心创新，再完成 M-P1-02、06。只有这一版可同时讨论预算匹配端到端效果和电力领域应用。

### 路线 C：完整增强版本

完成全部 P1/P2，形成统一 evaluator、角色消融、预算公平、未见电力集、风险—覆盖率和跨库/成本的完整证据链。

作者必须在开始大规模新模型调用前选择路线。资源不足时只能降低主张，不能保留强主张而只在 Limitations 中承认证据缺口。

## 8. 结果驱动的决策规则

- 八槽主表显示 selector 未超过开发冻结的最佳固定源：摘要不得把 80→101 解释为优于固定策略，只能报告相对 C000。
- 76 与 80 来自同一 artifact/evaluator：必须统一为同一结果；若不同，必须使用不同 artifact ID 和表题。
- 1,000 次顺序扰动显示大幅波动：默认策略必须改为开发冻结的去重/tie/abstention 规则，或明确承认不稳定。
- 预算匹配端到端实验无实际收益：删除 multi-agent performance advantage，保留审计与安全边界。
- 专家审核表现不足：不得用 execution equality 或 constructed-state agreement 替代业务语义正确性。
- 扩展 witnesses 几乎无增益或误拒高：Critic 降级为可选诊断模块。
- 公开仓库无法与论文版本一致：收缩 Data Availability，不得声称公开可完整复现。
