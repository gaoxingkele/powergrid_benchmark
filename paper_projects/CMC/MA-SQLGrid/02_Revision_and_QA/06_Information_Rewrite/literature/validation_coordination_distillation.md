- 目标：为 MA-SQLGrid 转投 Information 提供句式、叙事、理论深度及主张—证据对应关系的借鉴；不修改主稿。
- 一手材料：本目录 `info16110960.txt`（16 页）和 `info11050271.txt`（21 页），已按换页符分段通读，包括附录与参考文献。页码采用文本中的出版页码。
- 使用 academic-search 的一手来源与证据约束原则。本任务是对指定本地全文的分析，不重新检索、下载或统计引用量。
- 2020 年论文文本层含重叠文字及 `FOR PEER REVIEW` 残留，尤其第 3–4、8、11、18–19 页。以下不把重复层当作作者有意的句式重复，不评价其视觉版式；代码中疑似转录错误也不据此断言原程序不可运行。
- 两篇是个案样本，不代表 Information 的统一写作标准、最低理论要求或录用概率。以下“宜借鉴”“不宜照搬”均为分析意见；对 MA-SQLGrid 的建议是条件性方案，不表示已经核查其全部实验证据。

## 1. Çetinkaya（2025）：无金标准条件下的 LLM 信息抽取验证

题名：A Systems Approach to Validating Large Language Model Information Extraction: The Learnability Framework Applied to Historical Legal Texts。Information 16, 960；DOI：10.3390/info16110960。作者、题名、年份及 DOI 均见第 1 页。

### 1.1 句式风格：以验证对象统领方法，而非以工具清单起笔

摘要第 1 页依次回答“验证什么—在哪种数据上—得到什么量化信号—有什么外部对照—为何有意义”。主语围绕 framework、approach、analysis 转换，句子主要承担定义、报告或解释一种功能。它没有先逐个介绍软件组件，而是先确立缺少人工金标准这一约束。这种开篇对 MA-SQLGrid 的启示是：先说明电网信息查询的可核查困难，再引出 agent 分工，避免让“用了几个智能体”成为问题定义。

第 2 页 §§1.1–1.4 用“既有验证路线的局限—LLM 特有困难—系统观点—RQ 与贡献”组织段落。第 5 页 §2.3.1 通过对照句区分单模型泛化与跨模型可学习性，随后引出公式；这比先堆公式再解释目的更易读。第 6 页 Results 开头给出证据路线图，使读者知道内部一致性、外部模型、专家与错误分析各自的位置。

应避免照搬的部分是修辞强度：第 1–2 页的突破性描述、第 10 页 §4.1 的“范式转变”定位，以及多处将结果称为高度可靠，强于本文对代理指标的校准证据。建议 MA-SQLGrid 使用“在所测设置下显示”“支持某种解释”“尚不能排除”等与证据强度相符的表达。不要把“显著”“稳健”“可信”当通用连接词。

### 1.2 叙事逻辑：先内部、再外部、最后解释分歧

| 位置 | 叙事动作 | 对 MA-SQLGrid 的可迁移价值 |
|---|---|---|
| §1，第 1–2 页 | 把缺少金标准定义成方法学瓶颈，列出三个 RQ | 用一个真实、有限的问题统领系统设计，不用应用价值替代研究问题 |
| §§2.1–2.2，第 3–5 页 | 明确 20,809 篇语料、七类标签、OCR 与提示结构 | 先定义数据库、问题、SQL 与约束的对象及来源，再描述推理流程 |
| §§2.3–2.4，第 5–6 页 | 内部可学习性与外部 LLM/专家分开 | 将执行成功、语义正确、约束合规分别定义，不混成单一“准确率” |
| §§3.1–3.6，第 6–10 页 | 总体指标→模型间分歧→实例→语言特征→专家→学习曲线 | 总表后接可追溯错误案例及分层分析，解释收益在哪里发生 |
| §§4.4–4.5，第 11–12 页 | 限制与实践规则 | 限制应回扣实际指标的适用范围；未经校准不应写通用门槛 |

这种结构的长处是证据互补，而不是只增加实验数量。分类器重新预测标签、其他 LLM 的同意、人工共识和个例解释分别回答不同问题。其不足是正文多次将这些不同问题压缩成“已验证的数据质量”；证据呈现层次清楚，解释层却有越界。

### 1.3 理论深度：操作性指标充分，正确性理论不足

第 5 页式 (2) 将 Learnability Score 定义为四种分类器 macro-F1 的均值；§2.3.2 给出 TF-IDF、60/20/20 划分及 1000 次 bootstrap。这构成可操作的系统度量设计，但不是“高可学习性推出语义正确”的定理。

特别需要区分三层命题：

1. 标签能否由其他学习器预测：表 2 直接支持。
2. 多个学习器是否在同一样本上作出相同预测：均值 F1 本身不是逐样本共识统计，不能仅凭式 (2) 得出。
3. 标签是否对应真实语义：仍需独立证据；系统性错误或提示词诱导的词汇捷径也可能高度可学习。

第 5 页以 PAC learning 为启发，但没有给出针对当前任务的假设类、噪声条件、样本复杂度或推导。因此更准确的定位是“受学习理论启发的经验验证框架”。第 11 页 §4.4 承认模型相关偏差与单标签限制，是必要的收束；它也削弱了第 7 页把供应商多样性直接等同于架构独立性的强表述。

### 1.4 主张—证据核对

| 主张与位置 | 实际证据 | 判断与借鉴 |
|---|---|---|
| 标签结构可被重新学习，§3.1 第 6 页 | 四分类器测试 macro-F1，均值 0.8906；表 2 | 对内部可预测性有直接支持，不能改称真实抽取准确率 |
| 外部一致性，§§3.2、3.5 第 7–9 页 | 442 篇五模型比较；338 篇专家比较；κ 分别约 0.785、0.786 | 可支持所抽样文本上的一致程度；样本选择与排除规则决定解释边界 |
| 专家基准可靠，§2.4.2 第 6 页 | 两位专家，50 篇校准；分歧讨论，未解决项排除 | 排除困难项可能提高表面一致性；需报告排除数、分母及困难项表现 |
| 分歧源于真实语义边界，§3.3 第 8–9 页 | 157 篇存在模型分歧；表 4 展示两例 | 个案支持解释的合理性，不能排除共同偏差或标签优先级造成的结构；附录 A 第 14 页明确固定类别优先次序 |
| 内外部度量有强相关，§4.1 第 10 页 | 一个整体 Learnability Score 与两项整体 κ | 不能由一组汇总值估计相关；须跨数据集、扰动或多条件测量 |
| 领域无关、质量分档，§§4.2、4.5 第 10–12 页 | 单一历史法律语料；提出 0.85、0.70 等阈值 | 尚缺跨域与阈值校准证据，不宜当作成熟通用规则引用 |
| 知识图谱收益，§2.5 第 6 页、§4.3 第 11 页 | 节点/边设计与图示 | 能支持构建路径，不能等价为下游任务效果或实体/关系抽取质量已获验证 |
| 定向标注将提高 2–3 个百分点，第 12 页 | 未来工作中的估计，未见对应实验或估算模型 | 必须保留预测性质；MA-SQLGrid 不可仿写未实测增益 |

附带一致性检查：§3.7 第 10 页给出约 200 美元、每篇约 0.01 美元、每篇 5 秒及总时长 28.9 小时。它们提供有用的成本叙事，但未清楚分离主抽取与全部验证成本。借鉴时应列计费口径、串行/并行口径，而非仅报总数。

## 2. Gharbi（2020）：规划与分布式任务分配

题名：A Social Multi-Agent Cooperation System Based on Planning and Distributed Task Allocation。Information 11, 271；DOI：10.3390/info11050271。元数据见第 1 页。

### 2.1 句式风格：定义—枚举—条件分支的工程说明型语言

第 1 页 Introduction 先列 agent 假设，再列五个规划阶段和论文贡献。第 6–7 页 §5.1 用发起者/参与者、BUSY/IDLE、接收/拒绝/确认等具体对象描述协议，条件句与枚举提供清晰的执行语义。这种语言适合 MA-SQLGrid 的角色权限、消息输入输出和失败返回；比“智能协同实现闭环”一类抽象表述更可复核。

第 3–6 页连续使用 RARM 生产系统例子，把传感器、动作、资源和决策连接起来；第 9–14 页又给实现片段。优点是抽象对象始终有实例对应，缺点是框架教程与研究贡献混排，占据较长篇幅。MA-SQLGrid 可借鉴贯穿例子，不宜把 API 类层级和样板代码大段放主文。

第 17–19 页多用“图中可见—本方法最好/高效”的报告式句子，易懂但量化比较不足。建议写“在条件 C 下，指标 M 相对基线 B 变化 Δ；该现象与机制 X 一致，但没有排除 Y”，避免以“显然”替代证据。

### 2.2 叙事逻辑：运行例子贯穿概念、协议与验证

全篇顺序为：问题和假设（§1，第 1–2 页）→相关方法类别及差异（§2，第 2–3 页）→生产系统例子（§3，第 3–4 页）→单 agent 规划（§4，第 4–6 页）→任务分配协议与实现（§§5.1–5.4，第 6–14 页）→形式化性质（§5.5，第 15–16 页）→三项性能比较（§6，第 16–19 页）→结论（§7，第 19 页）。

可借鉴的是从“单体行为”到“交互协议”，再分别验证协议性质与执行性能。对 MA-SQLGrid，应该让每个 agent 的输入、输出、允许操作、状态转换与终止条件先可理解，再讨论多 agent 系统效果。不能以一张多框架构图替代协议定义。

不足在于相关工作中的类别性比较过强：第 2–3 页对 CNP、阈值方法、集中式和混合式方法的局限有绝对化表述，而本文实测仅比较两个具体基线。MA-SQLGrid 的相关工作应比较明确实现、预算与适用假设，不把某一实现的限制扩展成整个方法家族的必然缺陷。

### 2.3 理论深度：具有形式模型，但须按逻辑量词精确解释

第 6 页定义 agent、资源、任务集合与可分配条件；第 15 页 Figure 5 给 Petri 网，第 15–16 页 Table 1 对应转移含义；第 16 页列三项 CTL 性质及一项 eCTL 性质，报告 ITS-CTL 检查为真。这比仅用数学符号重述流程更具体，因为存在明确待验证对象和性质。

但其证明范围应严格限制为给定模型中的所列性质：

- Property 1 的 `AG(P1 => EF P9)` 表示在所有可达状态，若 P1 成立则存在到达 P9 的后续路径；不是所有执行路径都必然最终到达 P9。存在可达性不能写成无条件活性保证。
- Property 2 的 `EF P1 AND EF(P11 OR P15)` 是两项存在可达性，公式自身未表达每次发起后都收到响应的时序关联。
- Property 3 的 `NOT EF(P5 AND P6)` 对互斥安全性较直接，但仍依赖 P5/P6 的模型含义。
- 未见完整模型文件、状态空间规模、参数化系统证明及与 JADE 程序的等价性论证；eCTL Property 4 的语法和语义不在本分析中作额外背书。

因此，MA-SQLGrid 若只有限次重试规则与实验日志，应写“实现规定的终止上限”或“实测满足”，不能仿写为已形式证明全流程可靠；若新增形式验证，则需同时提供状态、异常分支、公平性/通信假设与可运行验证工件。

## 3. 对 MA-SQLGrid 的合并写作建议

两篇最值得组合的长处，是“960 的多层验证组织”与“271 的交互协议具体化”，不是其强修辞。

1. 引言以可检验瓶颈开篇：说明电网自然语言问题转成 SQL 时有哪些易混淆对象或约束；只列本研究真的测量的研究问题。
2. 方法先给任务和边界，再给角色：用户问题、schema、候选 SQL、验证反馈各是什么；哪个角色能读什么、改什么、执行什么；失败如何返回，何时停止。
3. 设一个贯穿案例：同一问题对应检索上下文、初始 SQL、被拒原因、修订 SQL 与最终结果。仅用已留存且可核查日志，不编造“代表性案例”。
4. 把证据分层：语法/执行成功不等于语义正确；多 agent 同意不等于独立真值；约束通过不等于所有业务条件正确。每项主张单独绑定指标、样本与分母。
5. 理论内容服务实际保证：可给状态机、约束定义、重试上限与成本表达式；若没有定理及适用假设，不把流程命名升级成理论保证。
6. 实验解释使用“结果—机制—替代解释—边界”：例如消融收益只能支持该模块在所测组合中的作用，不能单凭总体提升断言一般协同优势。
7. 结论保留边界：外部模型、跨库、复杂查询、成本与失败条件未测的部分标为未评估；未来工作不得携带未实测的改善百分比。
