### A1. 句式与段落风格

优点是读者导航非常显式：引言先交代 SQL 学习困难，再解释原有 PLAS 题型为何不足，最后引入 SDP 以及生成—人工验证—练习的流程（第 1–3 页，§1）。方法多以参与者作主语：教师选择主题和模型、生成器产生题目、教师验证、学生提交、系统记录（第 8–12 页，§5）。抽象系统因而落到可理解的动作和输入输出上。

值得迁移的不是具体措辞，而是三种句法功能：

1. “已有功能能处理 A，但未覆盖 B，因此新增 C”：适合 MA-SQLGrid 明确一般 SQL 生成与领域信息访问之间的差距。
2. “输入是什么—执行什么检查—通过后进入哪里”：适合解释各 agent 的责任、交接产物、拒绝条件。
3. “结果是多少—说明什么局部现象—不能推出什么”：应比样本更严格地贯穿摘要、讨论和结论。

不足是导航句和自我评价偏多。§2 常以相似模板逐篇列举，段尾又笼统汇总“有潜力/提高质量”，主题间的对比不够集中（第 3–6 页）。第 2–3 页还存在同一模型比较结论的连续重复。多处使用确保、证明、可靠等强措辞，却没有同步给出适用条件。这些属于该文的表达与编辑问题，不能作为目标风格模仿。

### A2. 叙事逻辑

主链条清楚：新手 SQL 困难 → 原有题型只覆盖识别/理解 → 需要实际写查询 → 教师出题负担 → AI 辅助生成 → 双层评估（生成质量与学生使用）。§1.1 五项贡献分别覆盖题型、自动化、评估、模型比较和可行性（第 3 页）。生成器和学生系统分别设实验与结果，避免把生成器可执行性混同为学习效果（第 14–22 页）。

但框架铺陈过长：§3 软件/数据集、§4 原系统回顾、§5 提案，直到第 13 页才进入实验设置；同一流程被多次复述。MA-SQLGrid 可保留整体图和一个端到端示例，把通用 LLM 与常见数据库背景压缩，把篇幅给输入表示、机制差异、错误恢复及可复核评估。

更重要的优点在 §8.5：作者明确承认无对照组、无前后测、单机构小样本，最后把解释边界收回到可用性与任务完成（第 23–24 页）。这个边界声明应前移，不能只放在限制段修补前文过强论断。

### A3. 理论深度：设计解释有，但机制验证弱

引言及 §2.5–2.6 引入认知负荷理论和形成性评价，用环境简化、循序练习与即时反馈解释设计（第 2、5–6 页）。这比仅罗列工程模块更有动机，但本研究没有直接认知负荷测量，也没有建立“功能改变 → 认知负荷改变 → 学习提升”的可识别因果链。正确率和 SUS 是不同构念，不能替代认知负荷或长期学习增益。

§8.2–8.3 将高正确率、低提交次数及可用性分数进一步解读为降低认知负荷、比传统方法更有效地内化知识；与 §8.5 的谨慎限制并不完全一致（第 23 页）。MA-SQLGrid 不应为了“理论深度”附会认知理论或信息论。更可取的是以已有实现为基础明确：信息在哪个步骤缺失或被误解、哪个机制针对哪类错误、用什么现有实验能检验。若没有随机对照或组件消融，只能称机制解释或设计动机。

该文的方法贡献主要是可操作流程、习题实例及等价答案集合，并非形式化语义等价理论。增强字符串匹配接受已列出的语法变体，但不能据此宣称覆盖 SQL 的一般语义等价（第 12 页，§5.4；第 23 页，§8.5）。

### A4. 证据强度与可复核性

可借鉴之处：

- 把主观教学质量与客观纠错次数区分为不同指标，并列出操作性定义（第 14 页，表 5）。
- 两位有教学经验的评估者独立评分，报告一致性，附录 C–H 提供主题级评分（第 14–15、28–31 页）。
- 保留失败信息：Gemini 的部分主观评分更高，而 GPT 的运行纠错次数更少；没有把全部指标包装成单一赢家（第 19–20 页，表 12–13）。
- 学生实验交代样本、时间、任务、允许反复提交和 SUS 项目；JOIN 题难度单独呈现（第 16–22 页）。

必须避免照搬的证据缺口：

1. **样本单位口径**：§7.1.1 称 220 assessments、每模型 110 problems；附录却是每模型 11 个主题的两名评分者分值。单题到主题的汇总过程不够清楚。不能把主题汇总行当成 220 条独立原始观测（第 18、28–31 页）。
2. **一致性口径**：§6.1.5–6 报全局线性加权 κ=0.631；表 11 是各指标 κ=0.72–1.00。两组数值不必然矛盾，但加权、合并与统计单位的关系没有充分解释。评分一致也不等于评分正确，更不消除所有偏差（第 15、18 页）。
3. **结果单位**：表 14 的正确率为 95.20，而 SD=0.08，百分数/比例单位未交代；“Submission Time”在相关文字中实际表示提交次数，容易误读为时长（第 20 页）。
4. **学生任务边界**：生成的 11 个实例共 67 题，课堂实际测试前 5 个实例共 29 题，不应把整套题覆盖归入学生验证（第 15–17 页）。
5. **减负未直接计时**：教师工作量降低是目标和讨论主张，但缺少人工出题与 AI 加人工修订的总工时比较；人工验证成本不能从工作流中消失（第 8–12、23 页）。
6. **“就绪”定义不可合并**：回答完整度满分并不表示查询无需修正；表 13 仍有执行修正。结论中的“可直接使用”需受此限制（第 19、24 页）。
7. **引用支撑待核实**：§2.6 把文献 [26] 引入“SQL 学习”语境，但参考文献题名是高中生物课堂反馈研究。这不是外部查证后的错误判定，却足以要求回查原引用，而不能从该文二次转引（第 5、33 页）。

### A5. 对 MA-SQLGrid 的可执行迁移

优先采用“完整系统、清楚工作流、逐层评估、主动限制”的叙事，不采用“少量应用结果证明广泛可靠性”的论证。系统工作流中明确人工介入、模型生成、规则检查和执行反馈的边界；精度、可执行性、运行代价、领域正确性分别报告。如果没有用户实验，不添加可用性或工作负担降低结论；若没有等价判定保证，不把执行成功写成语义正确。

| 研究对象 | ER 概念构造到可读文本的解释；与 NL→SQL 方向不同 |

### B1. 句式与段落风格

相比样本 A，这篇的句子更围绕概念和判断条件组织。引言先说明 ER 表达对象，再说明图式之外为何需要文字解释，随后将已有 Text-to-SQL 与本研究的 ER-to-text 清楚分开（第 1–4 页）。§3.1 采用紧凑表示、符号注释和示例串联，而不是只给架构框图（第 5–6 页）。

最值得借鉴的段落单位是“定义对象 → 给出具体构造 → 指出误读 → 展示干预 → 解释信息变化”。§3.3.3 对三元关系和泛化的解说把输入、无提示输出及有提示输出相互关联，读者能知道提示究竟修正了什么，而非仅被告知提示有效（第 9–11 页）。

仍有压缩空间：F1、perplexity、ROUGE 的教材式定义占据较多篇幅；结果段重复逐模型均值和标准差，部分信息可留在表格。对于 MA-SQLGrid，应优先解释执行正确性与领域语义正确性之间的差别，而不必长篇重复通用指标定义。

### B2. 叙事逻辑

三个 RQ 构成可追踪的研究骨架：能否识别构造、生成文本质量如何、怎样用提示改善（第 3 页）。方法定义输入形式、建立包含不同构造的案例集、探索提示、再按不同指标测量；补充大型 schema 检查范围边界（第 5–16 页）。研究重心是能力诊断和局部改进，而非将管线复杂性本身当作创新。

迁移价值在于：MA-SQLGrid 可以在现有证据允许下把问题拆成“整体是否改善”“哪些领域错误仍存在”“哪些模块对应哪些增益”，并使结果小节逐项回应；不能先写多个 RQ 再仅给一张总体准确率表。

该文也存在 RQ–证据不完全闭合：提示策略选择与 hints 改善以探索叙述和实例说明为主，没有在正文提供覆盖全部模型/案例的完整有提示—无提示量化矩阵（第 8–11 页）。因此“诊断导向的叙事”值得学，“机制效应已充分验证”则不能跟着写。

### B3. 理论深度：操作性语义比抽象标签更有效

研究没有新定理，但通过对象定义获得了技术深度。§3.1 明确实体、关系、基数、外部标识符、泛化及覆盖约束的表示规则；§3.3.2 把“识别正确”限定为描述构造属性和所表达信息均正确（第 5、8 页）。§3.3.3 又说明三元联合关系不能被简单替换成多个二元关系，泛化需说明父子角色、继承和覆盖约束（第 9–11 页）。这让“理解 schema”不再是泛泛能力标签。

提示本身很简约：给复杂构造添加类型标签（第 8 页，表 3）。它的可解释性来自“显式类型标注减少构造误判”的任务层逻辑，不意味着证明了模型内部推理过程。

MA-SQLGrid 最值得借鉴的是：先对领域约束和 agent 交接信息给可操作定义，再解释错误如何穿过管线以及哪一检查可发现它；若有现成错误样例，标注是 schema linking、连接路径、过滤条件、聚合粒度还是领域约束失配。只有实现和实验确实覆盖时，才能写入稿件；不能为了理论完整而新增不存在的机制。

### B4. 证据强度与可复核性

优点：

- 13 个案例横跨不同应用域，表 2 不只列案例名，而是逐例统计实体、二元/三元关系、泛化、标识符和属性类型（第 6–7 页）。比只写数据量更能说明测试覆盖。
- 多指标保留不同维度，并讨论 Llama 2 低 perplexity 与低构造 F1 的反差：流畅不等于忠实（第 13–15 页）。这是对 MA-SQLGrid 极有价值的论证结构：能执行不等于答对，更不等于领域约束满足。
- 提供总体均值与标准差、分布图，公开测试资料声明，增加可检查性（第 13–17 页）。
- 扩展案例含 84 个组件、20 个实体类型、14 个关系，用来探索复杂度变化，而不只重复原规模（第 15–16 页）。

不足与边界：

1. **评估细节不足**：构造 F1 在 §3.4.1 先描述与参考文本重合，再说比较输入 ER；怎样抽取与匹配构造、部分属性错误如何记分、人工评分者与一致性，正文未充分交代（第 11–12 页）。迁移时必须把评估脚本或判定规则明确到可重复执行。
2. **perplexity 可比性不足**：正文给出公式，却没有清楚交代统一评分模型、tokenizer 与实现配置；闭源模型之间不能仅靠一张 PPL 表理解其比较协议。所谓低于 50 即可接受也不应当作通用阈值照搬（第 12、14 页）。
3. **重复与不确定性不足**：案例间 SD 不等于重复生成的不确定性；正文未完整报告模型具体版本、采样参数、独立重复次数和配对显著性检验。均值差不能自动写为已证实的优越性。
4. **提示策略证据不足**：零样本“不够用”、few-shot 与 CoT 相近的判断，没有正文量化对照支持；示例说明能解释机制，但不能替代全样本消融（第 7–8 页）。
5. **规模外推偏强**：补充实验只有一个大 schema、一个模型；由此证明普遍可扩展、现实环境适用或跨多指标稳定过强。其 ROUGE-1 F1 为 0.422，主实验 GPT-4 均值为 0.563，也提示不能笼统称所有指标不变（第 15–16 页，表 6–7）。
6. **用户收益未验证**：文档可读性、非技术人员理解与知识传递是合理用途，但无面向这些人群的用户实验；结论称自动描述保持与 ER 一致，亦需受模型可能误述构造的实测限制（第 16–17 页）。

### B5. 对 MA-SQLGrid 的可执行迁移

以“信息/语义对象—错误类型—针对性机制—可核验结果”作为方法叙事骨架。优先增加已有资料支持的表：任务类别及复杂度覆盖、agent 输入输出和约束、各类错误与失败案例。对于生成查询的评价，分清表面语法、可执行性、结果正确性与领域语义；不要以文字相似性替代查询正确性。若旧实验没有模块级消融或重复运行，明确列为限制，不能靠重写补出结果。

## 两篇合并后的编辑决策

| 维度 | 值得采用 | 明确不采用 |
|---|---|---|
| 定位 | 面向具体信息任务，先定义输入、输出、用户问题 | 仅因同刊有 LLM/数据库文章便声称目标期刊匹配或录用可能性 |
| 方法 | 人/模型/规则边界清楚；可操作语义和端到端示例 | 用多个模块名称或泛化理论标签代替机制解释 |
| 结果 | RQ 对应结果；不同指标允许不同赢家；失败样例解释原因 | 仅总体准确率就宣称可靠、可扩展、减负或可部署 |
| 理论 | 对象、假设、约束和错误传播有定义 | 无测量地声称因果机制得到验证 |
| 证据 | 样本单位、指标单位、配对与重复结构显式说明 | 把主题汇总行当独立观测，把跨案例 SD 当重复试验稳定性 |
| 语言 | 功能动词、边界条件、结果后接有限解释 | 重复导航句、笼统赞誉、把限制留到文末才补救 |

建议用于后续重写的最低门禁：每条摘要结论能定位到一个已有表/图/实验；每条贡献对应一个明确新内容而非软件常规功能；每个“提高/减少”交代比较对象与单位；每个“可靠/可扩展/泛化”有测试范围限定；引用须回到原文核实，不从样本文献的相关工作段落直接转引。

本蒸馏只提供编辑与审阅依据，没有检查 MA-SQLGrid 当前实验、没有替作者作最终科学判断，也没有新增主稿结论。
