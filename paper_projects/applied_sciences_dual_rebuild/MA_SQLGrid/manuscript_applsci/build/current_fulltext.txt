Abstract

6

Natural-language access to power-grid maintenance data requires generated SQL to be
grounded in the supplied database context, remain read-only, and return the intended result.
We present MA-SQLGrid as a controlled study of two frozen, GridDB-tailored prompt
interventions: a context-package factor and a composite structural/SQL-operation hint.
Qwen2.5-Coder-7B Q4_K_M and Granite-3.3-8B Q4_K_M each produced one prediction for
every cell of a paired 2-by-2 design over 180 questions (1440 predictions total). After Holm
adjustment of a nine-test execution family, no factorial effect or cross-backbone modifier was
promoted; a separate secondary manipulation-check family showed increased projectedcolumn adherence under the hint. A prospectively frozen 700-call component study found
that presented value evidence improved Qwen execution by 0.1059 (95% compositionsensitivity interval [0.0282, 0.2013], adjusted p = 0.0310) but not Granite execution, while
deterministic candidate selection was not promoted. We additionally re-executed every
archived prediction on 15 deterministic semantic stress states and three insertion-order
diagnostics. Two blinded technical reviewers held all 114 order-sensitive questions, leaving
66 questions for an automated 15-state logical-AND endpoint. Suite rates ranged from
0.6212 to 0.8182 across cells, and none of nine suite effects survived Holm correction. This
retrospective stress test reduces single-snapshot ambiguity but is not a human semantic
audit. GridDB is a synthetic, development-visible 8-table/98-row database; no multi-run
replication or external-database accuracy is claimed. The evidence supports a reproducible
bounded case study, not a universal prompt recipe or operational generalization claim.

aggregation conventions. Text-to-SQL systems promise a more accessible interface: a user
asks a question in ordinary language, and a model produces a query whose execution
returns the requested records. In an engineering setting, however, plausible-looking SQL is
not sufficient. A query may execute against the wrong table, omit a required aggregation,
return an unintended projection, or silently use an identifier that exists but has a different
domain meaning.
Modern language models can translate questions into SQL when supplied with schema
context, demonstrations, or constrained decoding. Established benchmarks such as Spider
emphasize generalization across databases, while constrained decoders such as PICARD
show the value of preventing invalid token sequences [1,2]. Subsequent work has explored
schema linking, execution-guided selection, prompt design, and large-language-model
evaluation [3–5]. These advances do not remove an applied design question: which parts
of the database context and output contract should be placed in the prompt, and do their
effects persist across model backbones?
Schema presentation, value exposure, domain normalization, and answer specification
are often changed together. A system may shorten the schema, replace a global value
dictionary with question-matched values, add normalization rules, and state SQL-operation
requirements in one revised prompt, then attribute any improvement to “schema selection”
or “formatting.” Such labels would be inaccurate here. MA-SQLGrid instead audits the
two interventions actually executed: a bundled context package and a question-derived
composite structural/SQL-operation hint. Each question appears in all four cells, so
package effects and their interaction can be estimated without confusing question difficulty
with prompt condition.
The structural endpoint is deliberately separated from semantic correctness. A response can return the requested number of projected columns while retrieving incorrect
content. We therefore make strict execution equality the primary endpoint and use one
common-target projected-column diagnostic in every cell. This diagnostic requires successful execution and equality between the result-column count and a single project-authored
target frozen per question; it does not validate row granularity, ordering, or meaning.
A useful engineering conclusion must therefore be based on the executed result, not on
structural conformity alone.
The revised study also separates canonical evidence from development-visible material. The primary GridDB corpus contains 200 questions, of which 20 are development
records and 180 form the factorial evaluation partition. This partition has been used in
prior local development and is therefore not described as a newly administered sealed
benchmark. Two local, quantized instruction backbones were run under frozen configurations, and independent audit scripts directly re-executed all 1440 predictions. An earlier
interrupted Qwen directory is quarantined and excluded from every canonical table.
For external scope, we materialize relational pilots from RTS-GMLC and SimBench.
Their schemas and automatically constructed question–SQL candidates provide a realistic
test of protocol plumbing, safety checks, and schema portability. They do not yet provide
human-gold external accuracy: zero of the 91 external candidates have completed the
prepared two-reviewer adjudication process. A Qwen diagnostic run over these candidates
is retained outside the canonical evidence chain because comparing model outputs with
automatic candidate SQL cannot substitute for expert semantic validation.

2. Related Work

100

2.1. Text-to-SQL and Cross-Database Evaluation

101

Text-to-SQL research has progressed from template and grammar systems to neural parsers and instruction-tuned language models. Spider established a cross-domain,
cross-database setting in which train and test databases differ, forcing models to interpret
unfamiliar schemas rather than memorize query templates [1]. Its difficulty also highlighted
the need to evaluate structural decisions such as joins, nesting, aggregation, grouping, and
ordering. Later benchmarks and surveys catalogued continuing challenges in schema
linking, compositional generalization, ambiguous questions, and realistic database content
[3,6,7].
Execution-based evaluation answers a question that string match cannot: whether
the predicted query produces the intended result on a particular database state. Exact
SQL match can penalize semantically equivalent queries, whereas execution equality can
fail to distinguish nonequivalent queries on an insufficiently discriminating database.
Applied work should therefore freeze the execution contract, retain the predicted SQL,
and state the database boundary. In this study, strict result equality is primary; projectedcolumn conformity and error categories are separate diagnostics. We do not claim semantic
equivalence beyond the frozen database instances.
Constrained decoding and execution guidance reduce invalid outputs. PICARD incrementally rejects tokens that cannot form admissible SQL [2]. Execution-guided approaches
test candidate queries against a database and use failures or results during selection. MASQLGrid uses a lighter boundary: the generator is prompted once under a frozen condition,
then a deterministic parser and read-only validator classify and execute the output. No
gold SQL or gold result is available during generation or candidate selection.
Large language models make prompt context a central design variable. Schema serialization, examples, column descriptions, value samples, and explicit output instructions
compete for a finite context budget. Empirical studies show that model performance
can depend strongly on representation and demonstration choices [4,5,8]. Yet combined
prompt revisions do not reveal causal contribution. Our factorial design estimates two
interventions separately and shows that a prompt feature can improve response conformity
more reliably than semantic execution.

2.2. Schema Linking, Context Selection, and Response Contracts

131

Schema linking connects question spans to tables, columns, values, and relationships
[9–11]. A full schema preserves all available elements but may introduce distractors, longrange dependencies, and token cost. Compact context aims to retain question-relevant
elements while removing low-relevance structure. This creates a recall–precision trade-off:
excluding a needed join key is catastrophic, while retaining unrelated tables may confuse a
generator. Deterministic introspection and selection make this trade-off auditable.
Output contracts describe what a response should contain. In text-to-SQL, such
guidance can specify projected fields, row granularity, ordering, aggregation, grouping/HAVING, or LIMIT behavior. The intervention tested here is consequently broader
than an answer-format hint and is explicitly corpus-tailored. We record only a commontarget projected-column indicator independently of execution equality. The two endpoints
must not be merged: high column-count conformity shows reception of one structural
instruction, not correctness of the returned database content.
Recent domain-oriented systems combine schema retrieval, value grounding, decomposition, and repair, including CHESS and the Applied Sciences DKA-SQL study [12,13].
DKA-SQL is a direct power-grid text-to-SQL precedent, so our novelty is not being the
first grid text-to-SQL framework. Its published evidence, workflow, models, and corpora
differ materially from ours, and no official implementation or immutable prompt/code
release was located in the Round-1 audit; we therefore make no numerical superiority or
reproduction claim. A 2 × 2 design estimates the bundled context-package effect, compositehint effect, and difference-in-differences interaction. Repeating the same design for two
backbones is a sensitivity analysis, not a general model-family study.

2.3. Power-Grid Databases and AI-Assisted Access

154

Power-system datasets mix network topology, asset attributes, time series, costs, constraints, maintenance records, and event narratives. RTS-GMLC provides a reproducible
test-system resource with buses, branches, generators, loads, renewable profiles, reserves,
and dispatch-related data [14]. SimBench supplies benchmark networks for multiple voltage levels and scenarios [15]. Both resources can be transformed into relational databases
that exercise selections, joins, aggregation, ranking, and topology-oriented questions.
These public engineering resources are attractive for external validation, but database
availability does not create a text-to-SQL benchmark automatically. Natural-language
questions and reference SQL must be semantically reviewed, units and tie handling must
be specified, and ambiguous projections must be resolved. Automatically generated pairs
are useful for building and testing the pipeline, yet their agreement with a model output is
not human-gold accuracy. The present paper treats the external resources accordingly.
Recent work applies language models to grid-domain information extraction, including a semantic-dependency and lexical-embedding RoBERTa design in this journal [16].
Relational-provenance research in the same venue further motivates preserving query and
source lineage [17]. The central risk is that fluent output can be mistaken for validated
engineering reasoning. Text-to-SQL offers a comparatively inspectable interface because
the generated query and returned rows can be reviewed. That advantage depends on a
read-only execution policy, stable database provenance, and conservative claims about
what the execution demonstrates.

3.3. Prompt Packages and Factor Audit

209

The full package is constant across questions apart from the question text: all eighttable DDL and a sorted global dictionary drawn from permitted non-ID categorical, date,
and text columns. The compact package first matches permitted values, applies frozen
corpus-tailored phrase and normalization rules, selects seed tables/columns, expands
foreign-key connections to at most six tables, and serializes joins, matched values, and
predicate hints. If selection omits a needed element, the model cannot recover it from gold
metadata.
The composite hint can specify the expected projected-column count, row granularity,
ordering need, COUNT/AVG/SUM/MIN/MAX, GROUP BY/HAVING, exact projection fields, descending order, or LIMIT. Its serialization also differs between full and compact packages.
The estimand is therefore the effect of this frozen composite package as actually delivered;
it is not the effect of a generic answer-format sentence.
For the representative question “How many alarmed readings does each asset
have?”, F00 contains complete DDL and the global dictionary; F01 adds a two-column,
multi-row, ordered COUNT(*) hint. F10 contains six graph-expanded tables, the
sensor_readings.asset_id = assets.asset_id join and the normalization alarm_flag
= 1; F11 adds the corresponding two-column, multi-row, ordering and count instructions.
Across all 180 questions, question ID, database, common safety instruction, model settings,
one-call policy, parser, validator, and offline evaluator are invariant. Prompt-field auditing
confirms that F00/F01 always contain full DDL and the global dictionary, F10/F11 always

3.9. Prospectively Frozen Component Experiments

386

After the factorial analysis and review exposed the bundled nature of the prompt
packages, we froze a separate component protocol before generating its formal outputs. E1
isolates presented value evidence. Its V0 and V1 prompts share the question, selected schema,
join paths, composite structural hint, model settings, and candidate request; V1 alone
contains exact matched values and question-derived normalization-value evidence. This is
a presentation ablation, not a pure retrieval test. The intervention changes the prompt for
170 questions in 61 normalized-SQL groups; ten byte-identical cases receive V1 only and
are excluded from E1.
E2 evaluates a deterministic, reference-answer-independent candidate selector on all
180 V1 questions. Each response requests up to three candidates. The frozen ranker uses
only read-only safety, SQLite executability, output-column shape, ordering, non-empty
execution, and presented-value coverage; it seals its choice before gold SQL or results
are loaded. E2 compares the selected candidate with the first candidate. Rescue, harm,
selection-change, and oracle-at-three counts are descriptive, and oracle-at-three is never a
deployable result. There is no repair call.
E4 records paired telemetry for consecutive V0/V1 calls under deterministic balanced
AB/BA order. The formal schedule contains 350 scored calls per backbone—170 V0/V1
pairs plus ten V1-only calls—or 700 scored calls total, after four unscored warm-up calls per
backbone. Temperature, seed, backend, and loaded snapshot match within each backbone;
maximum output length is 600 tokens. An input whitelist excludes gold SQL, required
literals, annotated answer fields, and results before prompt construction.

to two tests within E1 and separately to two tests within E2. The two Granite-minus-Qwen
modifiers form a secondary two-test family. Positive component efficacy requires a positive
estimate, an interval excluding zero, and adjusted p < 0.05. The protocol does not define

5. Discussion

562

5.1. What the Evidence Supports

563

The clearest factorial result is the composite hint on the common-target projectedcolumn manipulation check. Both backbones show increases larger than 0.35 and survive
the separate secondary family. Explicit structural and SQL-operation instructions therefore
change projected-column adherence in this bounded experiment. Because the hint also
contains aggregation, grouping, projection, ordering, and limit rules, this result cannot be
reduced to generic formatting advice or promoted as independent semantic validation.

564

https://doi.org/10.3390/app1010000

20 of 24

Factorial execution is more conditional. All nine primary tests fail Holm correction,
even where composition-sensitivity intervals exclude zero. This divergence is not contradictory: randomization tests implement the predeclared finite-set promotion rule, whereas the
intervals show how estimates change when the empirical group composition is reweighted.
Neither is evidence from a random sample of databases or questions.
The multi-state stress test strengthens the negative conclusion. Requiring one archived
SQL program to agree with the gold query across 15 constructed states reduces every
cell’s success count relative to or equal to its T0 count, and no factorial suite effect is
promoted. This demonstrates that a single frozen snapshot can overstate reliability for
some predictions. It does not prove full semantic equivalence: the states are deterministic
constructions from one small database, the automatic subset covers only 12 normalized-SQL
clusters, and all order-sensitive questions remain outside the primary suite.
The compact/domain-grounded package does not show a uniformly positive independent effect. For Qwen its execution main effect is negative with an upper interval endpoint
at zero; for Granite it is small and uncertain. The package is substantially shorter, but
it simultaneously changes schema coverage, value presentation, join serialization, and
normalization. It is therefore neither a pure schema-selection ablation nor evidence that
shorter prompts improve accuracy.
The prospective component results sharpen but do not universalize the architecture.
Presented value evidence passes the efficacy rule for Qwen only; its zero Granite estimate
and non-promoted modifier preclude a replicated or universal value-grounding claim. The
deterministic selector yields rescues for both backbones but does not pass either adjusted
test. Deployment teams should therefore validate the complete model–prompt–database
combination under execution rather than assume that a stage label guarantees benefit.

570

5.2. Projected Columns versus Semantic Correctness

594

The gap between the common-target diagnostic and execution equality is a warning
against surface-only evaluation. In Qwen F01, projected-column conformity is 0.9667 while
execution equality is 0.7167. In Granite F01 the corresponding values are 0.8778 and 0.5556.
A model can return the requested number of columns yet select the wrong table, field, filter,
join, or aggregation.
The projected-column diagnostic remains useful because it localizes one interface
failure and shows that an intervention is received. It should be reported next to, not
substituted for, execution. Row granularity and ordering were present in prompts but are
not validated by this endpoint. Where a database state is insufficiently discriminating,
manual semantic review or test-database augmentation is also needed.

595

5.3. Implications for Power-Grid Data Access

605

An operational interface should expose the generated SQL, database snapshot, schema
context, and execution status. Read-only enforcement prevents accidental mutation but
does not prevent a semantically wrong query from returning plausible rows. Highconsequence decisions therefore require review of both the SQL and the source data.
The external diagnostic is useful precisely because it fails visibly. Missing-column
errors indicate that the model inferred familiar field names rather than grounding to the
actual schema. Prompt repair should target these mismatches, then be evaluated on new or
sealed items rather than repeatedly optimizing against the same 91 visible candidates.
RTS-GMLC and SimBench broaden the engineering structures represented in the
project: topology, generation, constraints, time series, and network elements. Their inclusion does not by itself validate maintenance-database generalization. A credible external

5.4. Reproducibility and Negative Results

619

The quarantined Qwen incident demonstrates why result directories need immutable
identity and process accounting. A directory containing more generations than the registered Cartesian design is not repaired by truncating it. The clean rerun provides a separate
evidence chain, and the audit confirms that the contaminated output contributed no canonical row.
Hash-bound artifacts reduce transcription and provenance errors. They do not make
an exposed test partition sealed, resolve a missing data license, or turn automatic candidates
into human labels. Reproducibility and evidential validity are related but distinct.
The compact/domain-grounded package NO–GO is a useful result. The stage remains
available for future selectors, but the paper does not assign it an independent benefit that
the current data do not support. The prospective E2 selector also remains a NO–GO for
promoted efficacy despite descriptive rescues. E1 supports presented value evidence for
one snapshot only. BIRD model baselines remain unexecuted, and the E4 latency records
remain diagnostic rather than comparative-efficiency evidence.

620

5.5. Limitations

634

The primary corpus is one synthetic 8-table, 98-row maintenance-oriented database
and only 180 evaluation questions. Questions map to 70 normalized-SQL dependenceproxy groups, 58 of them singletons; grouped procedures respect this mapping, but it
is not an authoring-template identifier and the corpus cannot represent the diversity of
production schemas, permissions, missing values, units, or data quality.
The evaluation partition was visible in earlier development. Gold fields are excluded
from prompts and the formal runs are frozen, but prior analyst exposure prevents a sealedtest claim. The two model snapshots use Q4_K_M quantization and one llama.cpp revision.
Results may differ for full-precision weights, alternative quantization, other runtimes,
stochastic decoding, or hosted models.
Only one generation is made per factorial prompt and one formal response per component condition. Temperature zero and fixed runtime settings improve repeatability, but
they do not quantify decoding variance or server nondeterminism. The second backbone
is sensitivity analysis, not replication, and no cross-backbone component effect satisfies
a replication rule. Multi-run inference would require a prospectively frozen hierarchical
analysis and materially greater compute.
Execution equality is database-state dependent. Different SQL statements may agree
accidentally on the current data, and minor projection differences may be judged wrong
under the strict contract. The contract is intentionally fixed, yet no single automatic metric
captures every notion of semantic equivalence.
The 15-state suite addresses accidental equality only within its constructed witnesses.
It was designed retrospectively, does not constitute an independent human semantic
audit, and cannot certify behavior on unconstructed values or schemas. Two blinded
technical reviewers conservatively held all 114 order-sensitive questions; qualified domain
reviewers must still resolve intended ordering, ties, units, and result granularity before
those questions support semantic claims.
E4 records paired telemetry under a frozen order, but the required efficiency attestation
is missing. Token deltas remain valid descriptive outputs; latency and throughput are
diagnostic, and no energy or memory measurement supports deployment-efficiency claims.

5.6. Future Work

675

The immediate external study should complete two independent expert reviews of
all candidates, retain disagreements, and adjudicate them under the frozen manual. A
subsequent confirmatory set should be newly authored or deeply rewritten after the prompt
and schema-repair work is frozen. This preserves a genuinely unexposed test.
The compact/domain-grounded builder should be redesigned around reference-free
coverage safeguards. Candidate columns and relationships could be accompanied by
explicit connectivity checks and a fallback to the full package when join paths appear
incomplete. The observed offline table/column recall cannot be used online because it
depends on gold-required fields. Any replacement safeguard constitutes a new intervention
and must be evaluated prospectively.
The completed E2 replay should be followed only by a newly frozen selector revision;
tuning against its visible rescues would make the present set development data. Efficiency
confirmation requires controlled warm and cold runs, common hardware, token accounting,
resident and accelerator memory, energy where possible, and separate model-generation
and SQL-execution latency.
After explicit human launch authorization, the technically frozen BIRD Mini-Dev protocol can add transparent direct, decomposition, schema-selection, and bounded executionfeedback baselines on the same two snapshots. Its 500/500 SQLite 3.40.1 gold-query
preflight is a mechanical gate, not model evidence. It must not be described as DKASQL
reproduction, because no official implementation was found. Additional backbones, sizes,
quantizations, decoding settings, and repeated runs would test whether the finite-set
execution contrasts persist.
