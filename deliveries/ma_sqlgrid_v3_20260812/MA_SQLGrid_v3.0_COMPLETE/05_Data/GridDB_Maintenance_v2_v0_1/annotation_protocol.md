# GridDB-Maintenance-v2 v0.1 Annotation Protocol

## Status

This benchmark is synthetic and deterministic. It is intended as a
pre-prepare-paper foundation, not as evidence of real industrial deployment.

## Construction Rules

- The schema is adapted from the previous MA-SQLGrid pilot and extended with
  additional assets, technicians, work orders, readings, and topology edges.
- Every question is authored against the frozen SQLite schema and deterministic
  rows generated by `scripts/build_griddb_maintenance_v2.py`.
- Every gold SQL query is executed during generation.
- Each question record includes required metadata: `question_id`, natural
  language question, gold SQL, order sensitivity, answer shape, SQL feature
  tags, involved tables, involved columns, required value literals, difficulty,
  and split.
- Dev/test splits are deterministic: `Q001`-`Q020` are dev and `Q021`-`Q200`
  are test.
- `Q081`-`Q200` are deterministic template-expanded questions over the same
  frozen schema, value inventory, and SQL verification process. They are added
  to reach the formal 200-pair threshold without claiming real industrial data.

## Scope

The benchmark covers filters, joins, aggregations, grouping, date predicates,
top-k/order-sensitive queries, NULL checks, scalar SQLite functions, topology
joins, parameterized domain-value questions, and executable-but-wrong failure
traps involving domain values.

## Restrictions

- Do not describe this v0.1 dataset as real operational data.
- Do not claim 1,000 pairs.
- Do not use test gold SQL in baseline prompts, example selection, or ranking.
- Do not report Spider, BIRD, or WikiSQL scores from this benchmark.
